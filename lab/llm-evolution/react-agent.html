ReAct：LLM Agent 的思考—行动循环

2026-07-27 · 约 15 分钟 · LLM 进化史 ⑥

2022 年 10 月，Shunyu Yao 等人发表了 ReAct——论文标题概括了一切：《ReAct: Synergizing Reasoning and Acting in Language Models》。

ReAct 的核心思想是：让 LLM 在「推理（Reasoning）」和「行动（Acting）」之间交替循环。这个看似简单的循环，成为今天所有 AI Agent 框架的基石。

一句话定位：ReAct 是 LLM Agent 的雏形——它第一次让语言模型学会了「自己决定什么时候推理、什么时候调用工具」。

一、背景：推理孤岛 vs 纯粹行动

在 ReAct 之前，让 LLM 完成现实世界任务有两种路径，但都有缺陷：

  • 纯推理（CoT）：模型在内部推理，但无法与外部世界交互——不能查资料、不能做计算
  • 纯行动（Act-only）：模型直接调用工具或采取行动，但没有推理指导——可能会做蠢事

ReAct 的洞察：推理和行动不是非此即 彼的选择——它们应该协同工作。

二、ReAct 循环

图1：ReAct 循环。Thought → Action → Observation 持续迭代，直到问题解决。

具体的 ReAct 交互示例

问题：旧金山湾区最高的城市是什么？

思考 1：我需要先知道旧金山湾区有哪些城市
行动 1：Search[旧金山湾区 城市列表]
观察 1：旧金山、圣何塞、奥克兰、弗里蒙特等

思考 2：现在需要查它们各自的最高海拔
行动 2：Search[旧金山 最高海拔]
观察 2：旧金山最高点：Mount Davidson，海拔 283m

思考 3：还需要查其他城市...
行动 3：Search[圣何塞 最高海拔]
...

最终答案：旧金山湾区最高的城市是...

ReAct 在所有任务上都超过了纯推理和纯行动。而且 ReAct 的推理轨迹还具有可解释性和可调试性的优势。

四、为什么 ReAct 如此重要

ReAct 没有发明任何复杂的新技术——它只是把两个已有的东西（推理 + 行动）组合起来。但正是这个组合产生了质变：

  • 推理指导行动：模型先想「我需要做什么」，再去做
  • 行动反馈推理：行动的结果（观察）被纳入下一轮推理
  • 自我纠错：如果行动结果不理想，模型可以调整策略
  • 透明可追踪：整个过程被记录下来，每一步都可审计

五、从 ReAct 到现代 Agent 框架

ReAct 是今天几乎所有 Agent 框架的架构基础：

框架与 ReAct 的关系
AutoGPTReAct 循环 + 持久记忆 + 任务队列
LangChain AgentReAct 的工程化实现，支持多种工具
Claude Code / OpenCodeReAct 循环 + 文件系统 + 终端工具
CodexReAct 循环 + 代码执行环境
Deep ResearchReAct 循环 + 搜索 + 阅读 + 综合

一句话总结：ReAct 用 Thought → Action → Observation 这个简单循环，第一次让 LLM 同时具备了推理能力和行动能力。今天所有 AI Agent ——从 Claude Code 到 Deep Research——本质上都是在实现 ReAct 循环。
