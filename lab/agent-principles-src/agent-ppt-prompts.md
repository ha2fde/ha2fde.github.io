# Agent 原理与实践

六讲 HTML PPT 的提示词。**上半部分是内容，下半部分是格式与交付。**

## 全系列

轴：**一是「用」，二三是「懂」，四是「接」，五是「扛」，六是「望」。** ——**这条轴是给写作定位用的，不许画进任何一章的页面里**（别做「六讲地图」那种页），否则就跟下面「自成一体」直接打架。

- 六章**全部重新写**，不沿用任何已有的 PPT 旧稿。
- **每章自成一体**：不出现「见第 X 讲」「这个留给下一讲」之类的跨章引用，边界一律用正面的自我限定表达（本讲讲到哪为止）。单独拿出任何一章都是完整的，合起来逻辑不重不漏。
- **详略按重要性分配，不按覆盖率均摊。** 这既不是面面俱到的深讲版——很多点其实不值得占篇幅；也不是每页一句话的精简版——关键点被一带而过。**最重点、最关键的部分要讲细**：给足过程、细节、真实例子、正反对照。不重要的直接省略或一句带过，只要不断主线。判断标准是：**这一页拿掉，读者对主线的理解会不会缺一块？** 不会就砍掉，省下的篇幅还给关键点。

## 第一章《装上你的第一个 Agent》

**主线**：客户端（Client）和模型（Model）是两回事，可以自由组合。

**讲什么**：Agent 和聊天机器人差在哪 · 客户端有哪些（顺带讲清代码补全 / 编程 Agent / AI 编辑器的区别）· 模型从哪来（云端几种买法 + 本地怎么跑，含硬件怎么对号入座）· 怎么换模型 · 要花多少钱（token 计价、缓存、按量 vs 订阅）· 怎么开始（按角色选一套、0 成本方案、第一次上手、安全底线）

**深度**：零基础、全员向，不写代码的人也要能跟。不讲原理。看完当晚就能跑起来一个能干活的 Agent，并且能自己估出这台机器跑得动多大的本地模型。**术语一律用规范中英文（首次出现给英文原名）；比喻只能辅助解释，不能替代术语。**

**边界**：只讲怎么用起来。「循环」讲到「思考 → 行动 → 看结果」为止，不展开具体的推理范式。「模型从哪来」是买卖口径，不是训练口径。

## 第二章《从图灵到 Transformer》

**主线**：每一代都在解决上一代的什么瓶颈。坐标系是三大流派（符号主义 / 连接主义 / 行为主义），主体叙事是前两者的交替主导与两次寒冬。

**讲什么**：从图灵到 Transformer 的完整历程。

**深度**：不需要 AI 前置知识。历史部分要讲到「每次寒冬具体是被什么问题打死的」；技术部分要讲到能徒手画出 Transformer 一个 block 的组成。内容详实，逻辑清晰，重点突出。

**边界**：止于「架构定型，但通用能力还没长出来」。不讲预训练语料、不讲对齐、不讲 GPT-3 之后。结尾「三派合流」只作一页收束，点到为止。

---

## 第三章《从 chat 到 agent》

**主线**：一个只会预测下一个词的架构，是怎么一步步变成会干活的 Agent 的。

**讲什么**：预训练 → 从纯续写对齐到对话（chat 就出来了）→ CoT → ReAct → tool call（agent 就出来了）。

其中 **ReAct 和 tool call 不是同一层的东西**，这点要点破：ReAct 是纯在提示词里教模型交替思考和行动（它的「行动」当年就是调 API），tool call 是把这件事做进训练和接口、变成结构化输出。不写清这层，读者会以为后者取代了前者。

另有上下文工程，它是贯穿整条链的横向话题，不是链条末端的一环。

**深度**：这是工程课，不是概念课。每一步都要讲实际的过程和细节——上一步差什么、这一步补什么、代价是什么——不能只给几个概念。不重要的可以略，重点必须突出。能用图讲明白的就用图。看完对整个过程的工程化重点要很清楚。正文一律用规范术语（自回归、下一词预测），「接龙」这类说法只作口头解释。

**边界**：只讲能力是怎么长出来的。tool call 讲到「模型能输出调用意图、执行的是宿主」为止，不展开 schema、报文格式与协议标准。

## 第四章《Agent 的协议层》

**主线**：模型只会输出文本。这一层要解决的是——让文本变成动作的那份**「约定」，由谁写、写在哪里、由谁执行**。下面几样各给了一套不同的答案。

**讲什么**：分三组，别摊成一串。

- **同一族的三样**：tools（含 schema、真实报文、一次完整往返）· MCP（分清 client、server、agent、原始服务提供者）· CLI。讲完抽共通点
- **抽象层**：ACI（Agent–Computer Interface）——接口是写给概率模型看的，不是写给编译器或人看的。**它只是上面三样的抽象，不是这一讲的总纲**
- **各自换了一个维度的两样**：Skills（本身 + 分发渠道 + 编写要点 + 应用场景 + 未来发展）管的是「该怎么做」而不是「能做什么」· A2A 的对端是另一个 agent 而不是一台机器。不要硬塞进 ACI 的框子里

**深度**：通过流程图分清实体、画清楚流程，这样对齐理解才深刻。**五样具体机制（tools / MCP / CLI / Skills / A2A）都要讲到同一个刻度**——能徒手画出它的实体关系和一次完整往返、能看懂它的真实报文或配置文件、能说出它什么时候不该用。不允许有哪一样是半透明的。**这是本讲对「详略按重要性分配」的一处刻意例外**——这一讲的价值就在于不留盲点，不许拿「这个没那么重要」当理由把某一样压薄。ACI 是抽象层，不适用这个刻度——讲清它是什么、以及由它推出的设计原则就够。

**边界**：只讲接口怎么定义与传递。不讲怎么评估、怎么保证上线后不出事；「人在环」只点到概念，不展开审批设计。

---

## 第五章《从 demo 到生产》

**主线**：先讲控制权，再讲工具，顺序不能反——编排方式决定了你需不需要框架。

**讲什么**：agent 项目大量卡在 demo 到生产这一步，死在哪 · 控制权连续谱（流程全写死 ←→ 模型全权决定），两端各自换来什么、付出什么 · 三种编排做法按**谁决定下一步**分——代码全决定 / 模型每步自己决定（ReAct）/ 代码定骨架、模型定局部，各在谱上什么位置，以及真实产品为什么几乎都是混合的 · **用不用框架是另一个维度**，别和上面那条混着讲：API / SDK / 框架各适配谱上哪一段 · 凭什么能上线，用**谁在问**来串（demo 到生产之所以难，是因为提问的人换了）：评估（元问题，没有它其它改进都无法验证，放最前）· 记忆（含 RAG）· 安全 · 治理 · 成本与延迟（很多项目不是技术不行，是单位经济算不过来）· 可观测性（≠ 评估：一个问好不好，一个问这次到底发生了什么）· 人在环（审批点放哪、粒度多大）

**深度**：决策型，会被反复回查。看完能在连续谱上指出自己项目的位置，并据此判断该不该上框架；手里能有一份直接可用的上线前清单。引证据时分清**已发生的**（落地率调研、企业复盘、失败案例）与**预估的**（如 Gartner 的项目取消率预测）——预估只当假设摆出来并注明是预测，不当现状用；数字标口径与核对日期。

**边界**：只讲下周就要做的决定，不讲趋势判断。协议细节不展开，但凡出现的术语要能就地交代清楚。

## 第六章《从 Agent 到 AGI》

**主线**：不预测，只梳理路径。

开场先处理 **AGI** 这个词：它没有公认定义（经济定义、能力基准定义、自主性定义各说各话），所以本讲不拿它当目标，而是问——从今天的 Agent 出发有哪几条路，各自的证据和瓶颈是什么，怎么判断哪条在走通。

**讲什么**：每条路线固定四栏——**主张是什么 → 目前有什么证据 → 已知瓶颈 → 如果它对了，我们会先看到什么信号**。最后一栏是关键，把预测变成可证伪的观察清单。

路线：继续 scaling · RL + 可验证环境 · 连续学习与记忆 · 多 agent 分工与经济体 · 世界模型与具身

**深度**：观点型，克制用图。四栏是硬结构，版面上就按四栏卡片走，不要为了「大字」把四栏压成一句话。但**每条路线占几页按它的分量给**，证据厚的多讲，单薄的一页说完，不强求一条一页——「会先看到什么信号」那一栏是要被留下来反复对照的，必须写实、可观察。

**硬约束：不给时间表。** 一旦给年份，这一讲就从「可证伪的路径梳理」变成算命，**本讲**前面那些可核实的部分都会被连坐。

# 格式与交付

## 产出

- 七个文件：`index.html` + `ch1.html` … `ch6.html`
- **每个文件各自完全自包含**：零构建、零 CDN、零外部资源，断网双击即开
- 每章一个版本。**不预设页数**——篇幅由「详略按重要性分配」那条决定：关键点该占多少占多少，既不为凑数注水，也不为省页压缩重点
- 文件名用纯 ASCII，方便以后直接推到静态托管；文件间跳转一律**相对路径**，不写域名
- **播放器代码在六章里逐字一致**，是同一份复制过去的，改一处就同步全部

## 索引页

`index.html` 只做入口：系列标题 + 六章列表，每章一句话说明和一个跳转链接。不承载正文内容。

**索引页不是幻灯片**：普通网页，没有 1280×720 画布、没有播放器、正常滚动。下面「画布 / 播放器」两节只管六个章节文件。

## 画布（只管六个章节文件）

**按 PC 阅读体验优化，手机不作为设计目标**——不做竖屏提示，不做移动端专门适配，小屏上能自动缩下去就行。

- 固定 **1280×720** 舞台。缩放比由 **JS 算**（读 `innerWidth/innerHeight`，取 `min(w/1280, h/720) × 0.96` 留一圈余量），写进 `transform: scale()`，`transform-origin:center`；监听 `resize`
- 桌面窗口从半屏拉到全屏、外接显示器上放大，都不裁切、不出滚动条（`body{overflow:hidden}`）
- **放大不设上限**：正文和图全是文字与 SVG，放到 4K 屏依然清晰，不该在大显示器上只占中间一小块

## 播放器（六个章节文件共用同一套）

**界面必须让路给内容。** 常驻的 HUD 会盖住正文，而且它一直悬在那里本身就是干扰。按下面来：

- **正文区留出安全边**：每页分页眉 / 正文 / 页脚三段，正文区高度 = 画布高 − 页眉 − 页脚。**正文永远进不了页脚**，所以页码在结构上就不可能盖住任何文字
- **页码放在页脚安全区里**，靠右，小字号、弱化色，不加边框不加底色
- **幕**＝章内的大段落（一章分若干幕，比如「开场 / 某主题 / 收尾」）。**幕名不做 HUD**——它本来就是内容，放进页眉跟标题一起排
- **进度条 2px**，压在页眉最上沿，低饱和，无动画，不额外挤占正文区
- **界面上不出现任何按钮**：翻页、全屏、概览全部只走快捷键和点击区
- **翻页只做 ≤150ms 淡入**，不做位移、翻转、滑动特效
- 键盘：`→` `PageDown` `Space` `J` 下一页，`←` `PageUp` `K` 上一页，`Home` `End`，`O` 开/关概览网格，`F` 全屏，`Esc` 关概览、退全屏
- 鼠标：点左侧 28% 上一页，其余下一页。**但点在 `<a>` 和代码块上不翻页，正在选中文字时也不翻页**——正文里有官方链接、有要复制的报文，不能一点就跳走。图是静态的，点图照常翻页
- 触屏滑动（阈值 50px）顺手支持一下触屏笔记本，不为它做别的适配
- `location.hash` 路由，`#12` 直达，翻页时同步；越界的 hash 夹到首/末页，不报错
- **内置溢出检测**：切页时比对正文区（留完安全边之后的那个高度）`scrollHeight` vs `clientHeight`，超出则 `console.warn` 并给该页加红框——这是验收工具

## 视觉

- **浅色主题**：页面底 `#e9edf3` · 幻灯片 `#ffffff` · 面板 `#f4f7fb` · 分隔线 `#e2e8f0`
- 文字：正文 `#1f2937` · 次要 `#5b6675` · 弱化 `#94a3b8`
- 语义色（都要在白底上看得清）：蓝 `#2563eb` = 数据流 / 客户端 · 绿 `#0e9f6e` = 产出 / 正确 · 橙 `#c2410c` = 工程要点 · 紫 `#7c3aed` = 模型 / 协议 · 红 `#dc2626` = 坑 / 失效
- **默认不上色**：正文是墨色，语义色只在真有那层语义时才出现；**一页里语义色不超过 3 种**，多了就不再是区分，只是花
- 只用系统字体栈（含 PingFang SC 回退），不引任何外部字体

**版心和字号也要定死，跟框图一个道理——随手拍是排版难看的同源病因：**

- 版心：左右边距 `56px`，页眉高 `72px`，页脚高 `40px`，于是**正文区固定 1168×608**，所有页共用，不逐页微调
- 字号六档，全系列统一：封面大标题 `44` · 页标题 `30` · 小节标题 `21` · 正文 `18` · 次要 `15` · 图注与脚注 `13`；正文行高 `1.6`
- **层级靠字号 + 字重 + 颜色三者一起做**，不只靠字号——小节标题和正文只差 3px，光靠字号分不开
- 要调可以整体调，但**不允许某一页单独换一档**

## 图

- 一律 **inline SVG 或 HTML/CSS 组件**，SVG 必须带 `viewBox`
- **禁用 ASCII 字符画**——等宽字符网格在不同字体下必然错位，换字体救不了

**框图先定尺寸系统再画，不许一个框一个数地随手拍。** 框大小和排列不好看，根源就是每个框的坐标和宽高都是临时定的：

- **先定一套框尺寸**（宽三档、高两档就够），本图所有框只能从这几档里挑
- **同类同尺寸**：同一层级、同一类的实体，宽高必须完全相同。**尺寸不同必须意味着类别不同**，不能因为文字多就撑大
- **框宽由该组里最长的那条文本决定，然后整组统一**，不要一个刚好塞满、另一个空半截
- **坐标全部落在栅格上**（如 20px 的倍数），图里不出现 137、243 这种数
- **对齐与等距**：同一行的框上下边对齐，同一列的框左右边对齐，相邻间距全部相等
- **连线只走水平 / 垂直**，转折用直角，从框边中点进出；箭头样式和大小全图统一；连线不许穿过任何框
- **位置带语义**：上下表示先后或层级，左右表示并列，两者不混用
- **一张框图最多 7–9 个实体**，超了就拆成两张——挤是不好看的主因。**时序图不按这条算**，它按泳道算：泳道不超过 4–5 条，消息条数不限
- 图四周留统一外边距，不贴边；圆角、描边粗细全图一致
- **SVG 里的文字要显式声明同一套字体栈**（不然中文会掉进 serif），字号不小于 `12`；描边不细于 `1.5`，太细的线缩小后会发虚

## 事实纪律

- 会随时间变化的数字（版本号、生态规模、价格、市场份额）一律标口径 + 核对日期，给官方链接
- 报文、代码、配置片段必须是真实形态，不编造字段

## 交付前验收

- Chrome headless 逐页测量：正文区纵向溢出 + 所有非 SVG 元素横向溢出，**六个章节文件**必须全部 `ALL-CLEAR`
- 三种 PC 窗口各测一次：`1920×1080`、`1400×900`、`980×660`
- 索引页不测溢出（它没有画布），只查：正常滚动、六个链接都跳得到对应文件
- 抽查 hash 直达（含越界值）、概览网格、全屏、点链接不误翻页
- 确认没有外部**资源**引用——查的是 `<script src>` `<link href>` `<img src>` `@import` `url()`；**正文里的 `<a href>` 官方链接不算违规**，那是「事实纪律」要求的
