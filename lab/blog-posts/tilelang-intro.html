TileLang：高性能 AI 内核的 Python 式 DSL

2026-07-25 · 约 12 分钟

在现代 AI 系统中，GPU 计算内核的性能至关重要。然而，编写高效的 GPU 内核（如 GEMM、FlashAttention）一直是一项极具挑战的工作 —— 开发者要么使用底层 CUDA/HIP 手动优化，事无巨细地管理每一级内存和线程调度；要么使用 Triton 等高级 DSL，但失去对硬件细节的精细控制。

TileLang（tile-lang）正是为了解决这个痛点而生的。它是一个基于 TVM 的领域专用语言，让开发者用 Python 语法编写 tile 级别的计算内核，同时保留对内存层次和线程映射的精细控制。由北京大学和微软研究院联合推出，论文已被 arXiv 2504.17577 收录。

为什么需要 TileLang？

在 TileLang 之前，编写 GPU 内核主要有三种方式：

  • CUDA/HIP：最灵活，但需要手动管理所有细节 —— 从全局内存加载、共享内存同步、寄存器分配、到 warp 级别的指令调度。开发效率极低。
  • Triton：以 tile 为单位编程，大大简化了开发流程。但其数据流表示不够直观，不支持显式的内存层次声明，一些优化（如 TMA、软件流水线）需要 workaround。
  • TVM/Ansor：自动调度搜索，但计算和调度分离，调试困难，且在复杂融合算子上的表现不如手动优化的内核。

TileLang 的目标是 兼顾 Triton 的开发效率和 CUDA 的性能控制：

TileLang 在设计空间中的定位：兼顾开发效率和性能控制力

核心设计：Tile 编程模型

TileLang 的核心抽象是 tile（数据块）。与传统逐元素编程不同，TileLang 的开发者以 tile 为单位思考计算：一个 tile 是一个在 GPU 内存层次中明确放置的数据块。

三级内存层次

TileLang 显式暴露了 GPU 的三级内存层次，开发者可以声明数据在哪一级放置：

TileLang 暴露的 GPU 三级内存层次 — Global / Shared / Fragment

在 TileLang 中，分配显式内存的 API 非常直观：

TileLang
# 在 shared memory 中分配 tile
A_shared = T.alloc_shared((128, 32), "float16")

# 在寄存器中分配 tile（累加器）
C_local = T.alloc_fragment((128, 128), "float32")

# 在 global memory 中的 tile（输入张量的一个切片）
A_global = A[by * 128, ko * 32]

代码实战：GEMM 内核

下面是一个完整的 GEMM（矩阵乘法）内核，展示了 TileLang 的核心编程模式：

tilelang_gemm.py
import tilelang
import tilelang.language as T

M, N, K = 1024, 1024, 1024
block_M, block_N, block_K = 128, 128, 32
num_stages = 3
threads = 128

@tilelang.jit
def matmul(
    A: T.Tensor, B: T.Tensor, C: T.Tensor
):
    @T.prim_func
    def kernel(
        A: T.Buffer[(M, K), "float16"],
        B: T.Buffer[(K, N), "float16"],
        C: T.Buffer[(M, N), "float32"],
    ):
        with T.Kernel(
            T.ceildiv(N, block_N),
            T.ceildiv(M, block_M),
            threads=threads
        ) as (bx, by):

            # 分配各级内存的 tile
            A_shared = T.alloc_shared(
                (block_M, block_K), "float16")
            B_shared = T.alloc_shared(
                (block_K, block_N), "float16")
            C_local = T.alloc_fragment(
                (block_M, block_N), "float32")

            # 清零局部累加器
            T.clear(C_local)

            # 分块迭代（带软件流水线）
            for ko in T.Pipelined(
                T.ceildiv(K, block_K),
                num_stages=num_stages
            ):
                # Global → Shared（异步拷贝）
                T.copy(A[by * block_M, ko * block_K],
                        A_shared)
                T.copy(B[ko * block_K, bx * block_N],
                        B_shared)

                # Shared → Fragment + 计算
                T.gemm(A_shared, B_shared, C_local)

            # Fragment → Global（写回）
            T.copy(C_local,
                    C[by * block_M, bx * block_N])

    return kernel
关键洞察：与 Triton 不同，TileLang 允许开发者显式声明每个 tile 在内存层次中的位置（global/shared/fragment），并通过 T.gemm 等算子表达计算语义。编译器通过 Layout Inference 机制自动推导出高效的并行化方案和内存访问模式。

编译流程

TileLang 的编译器将 Python DSL 逐步下译为可执行的 GPU 代码，整个过程分为四个阶段：

TileLang 的四阶段编译流程
  1. Python DSL 解析：@T.prim_func 装饰器解析函数体，构造 TileOperator 节点图
  2. Layout Inference：自动推导每个 tile 的线程映射模式和内存布局，确定最优的并行化方案
  3. LowerAndLegalize：通过 14 个子 pass 将高级算子下译为 TVM TIR（含边界检查、负索引归一化等）
  4. OptimizeForTarget：针对目标硬件进行优化（Tensor Core 指令匹配、流水线编排、寄存器分配），最终生成 CUDA/HIP 代码

TileLang 之所以能达到这样的性能，主要得益于其 Layout Inference 机制。传统的 tile DSL 需要开发者手动指定线程映射和内存合并模式，而 TileLang 可以根据 tile 的声明自动推导出最优的并行策略，同时将底层细节（如 shared memory bank conflict 避免、向量化加载）交给编译器处理。

支持的后端

TileLang 目前支持以下硬件后端：

  • NVIDIA CUDA：sm_70 到 sm_100，含 Tensor Core (WGMMA) 支持
  • AMD ROCm：gfx90a, gfx942, gfx950
  • Apple Metal：M 系列芯片
  • CPU：x86 和 ARM
  • Huawei Ascend（实验性）：AscendC / AscendNPU IR
  • CuTe DSL（实验性）：编译为 CUTLASS CuTe

安装和使用

安装 TileLang 非常简单：

bash
# 从 PyPI 安装
pip install tilelang

# 安装 nightly 版本（最新特性）
pip install tilelang -f https://tile-ai.github.io/whl/nightly

然后就可以用 @tilelang.jit 装饰器编写和 JIT 编译内核了：

Python
import torch
import tilelang
import tilelang.language as T

@tilelang.jit
def add(N: int, block: int = 256):
    @T.prim_func
    def add_kernel(
        A: T.Buffer[(N,), "float32"],
        B: T.Buffer[(N,), "float32"],
        C: T.Buffer[(N,), "float32"],
    ):
        with T.Kernel(
            T.ceildiv(N, block), threads=256
        ) as bx:
            offset = bx * block
            for i in T.Parallel(block):
                C[offset + i] = (
                    A[offset + i] +
                    B[offset + i]
                )
    return add_kernel

# 与 PyTorch 无缝集成
a = torch.randn(1024, device="cuda")
b = torch.randn(1024, device="cuda")
c = add(a, b)
print(c)

总结

TileLang 最大的价值在于它在易用性和性能控制之间找到了一个优雅的平衡点。如果你正在为 AI 模型编写自定义 GPU 内核，希望在提高开发效率的同时不牺牲性能表现，TileLang 是一个值得关注的选择。它不仅降低了 GPU 内核开发的门槛，还通过 Layout Inference 等机制提供了超越手动编写的可能性。
