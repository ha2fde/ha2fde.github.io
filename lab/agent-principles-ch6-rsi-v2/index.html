AGENT 原理与实践 · 第六章

让 Agent 改进它自己

递归自我改进（RSI）今天真实的形态：不是模型去改自己的权重，是模型去改自己的外壳。
外壳是代码，代码可读、可写、可执行、可评估、可回滚——所以它先被改起来了。
机制型 · 只讲这一件事 · 全部结论都指向可观察的对象

递归自我改进：这个词到底在说什么

日常说「AI 越来越强」是含糊的。RSI 有一个很窄的意思：系统用它当前的能力，去改进「产生这份能力的那套机制」。改的不是答案，是产答案的东西。下面三档必须分开——它们经常被混着说，但性质完全不同。
词的来历
1965 年 I. J. Good 说：如果一台机器在所有智力活动上都超过人，那么「设计机器」这件事本身也在其中，于是它能设计出更好的机器。
2008 年 Yudkowsky 给这个反馈回路取了名字：recursive self-improvement——AI 用当前的智能去改进产生智能的那套认知机制。
今天它有三种可能形态
① 直接改自己的权重——最激进，也最遥远
② 改训练流程——数据、目标、课程
③ 改部署系统——模型之外那一整套让它能干活的东西

本章只讲 ③。因为近期真实发生的 RSI，几乎全在 ③ 上。
本章的边界，先说清楚
不讲 self-play、合成数据、test-time training、连续学习——那些是在改模型，是另一条线。

本章只跟一件事：模型之外的那层系统，能不能被模型自己改，改到什么程度，为什么现在卡住。

被改的那个东西叫「外壳」（harness）

外壳是包在基座模型外面、编排整个执行过程的那套系统：它决定模型怎么想和规划、怎么调工具和行动、怎么感知和管理上下文、把产物存到哪、以及结果算不算对。你实际用到的能力 = 模型 × 外壳，而这两半的改法完全不同。
和早期「Agent = LLM + 记忆 + 工具 + 规划 + 行动」的区别
外壳视角额外要求四样东西：工作流设计（循环怎么写）、评估、权限控制、持久状态管理。
这四样都不是提示词技巧，更接近运行时和软件系统设计。
一个好用的类比：操作系统
操作系统的价值在于把复杂逻辑封装进去，把接口留得简单。外壳正在走同一条路——配置格式、工具接口、协议会逐步标准化，上层只面对稳定的调用面。
为什么 RSI 先发生在这一层
改权重需要训练、需要数据、需要评估权重好坏，任何一步都以天计且难以回退。
改外壳只需要写一个 diff、跑一遍测试、不行就 revert——这是一个模型今天就能操作的对象。

本章的主轴：被优化的对象，一级一级往上抬

把这几年围绕外壳的工作按「到底在优化什么」排一排，会看到一条很清楚的阶梯。它不是流派之分，是同一件事的深度递进——每上一级，能改的东西更多、搜索空间更大、对底座模型的要求更高、评估也更难。
这条阶梯就是本章第 8–18 页的顺序
每一级都会讲：被改的具体是什么、谁来提改动、怎么判断改得对不对、以及这一级现在做到哪儿了。五级看完，你会有一张完整的地图，知道任何一篇新论文该挂在哪一格上。
分界线在 ③ 和 ④ 之间
前三级改的是模型被怎么使用，后两级改的是使用它的那套程序。
跨过这条线之后，被优化的对象变成了可执行代码——搜索空间从「几种写法」变成「所有程序」，RSI 的味道也是从这里才真正出现的。

外壳先长出了三个稳定的设计模式

在谈「让模型改外壳」之前，先看人已经把外壳做成了什么样。这三个模式今天几乎出现在每一个严肃的 Agent 系统里，而且它们恰好是后面自动优化能下手的地方。
三个模式背后是同一条原则：把状态从对话里赶出去
只活在临时对话上下文里的产出，会随着对话推进而过期、被截断、被后面的内容淹没，而且没人能回头审它。落到文件系统上的产出才可以被别的进程读、被下一轮引用、被人检查、被自动化流程当输入。这一条在下半章会反复出现：一个东西要能被自动改进，前提是它先能被稳定地观察到。

看一个真实外壳：编程 Agent 装了哪些工具

编程 Agent 是目前外壳做得最成熟的一类，因为它天然满足两个条件：产物是文本，判据是能不能跑通。把它的工具面摊开，就能看清「外壳」具体是些什么东西。
工具组典型工具这一组在外壳里承担什么
文件系统glob grep ls read read_many write edit multi_edit apply_patch持久记忆的读写口。整个外壳的地基——后面所有自动优化都要靠它把状态存下来再找回来
Shellbash powershell唯一的「通用行动」出口。装依赖、跑测试、起服务都从这儿走
代码理解与版本lsp git_status git_diff git_commit让「我改了什么」变成结构化事实，而不是模型自己的回忆。归因的前提
外部上下文MCP 工具 · Skills把公司内部系统、领域知识、可复用手册接进来（协议层见第四章）
网页web_search web_fetch browser补训练数据里没有的、或已经过期的信息
产物读文档 / 读图 · 生成 HTML、图表、图片让输出不止是纯文本，能被人直接验收

注意最后两组
前六组是「让它把一件事做完」，最后两组是「让它同时推进很多件事，并且事后还查得清」。
自动优化外壳这件事，需要一轮跑几十上百次实验——没有这两组工具，回路根本转不起来。
这张表就是「可编辑面」的雏形
后面讲自动改外壳时，模型能动的东西基本就在这张表的框架内：工具的描述怎么写、工具的实现怎么改、哪些工具该加、哪些该删、什么时候该派子 agent。
第 15 页会把可编辑面正式切成七个部件。

外壳会不会被模型自己吃掉？

这是个真问题：今天写在外壳里的东西，很多是在绕过模型的短板。模型变强之后，这些补丁本来就该删掉。那外壳工程是不是一门注定短命的手艺？参照提示词工程的历史，答案是「一部分会消失，一部分不会」。
外壳工程正在往「元方法」上走
它优化的不再是某个答案，而是「得到更好答案的那套机制」。
这一句听起来抽象，但它就是本章阶梯从 ① 走到 ⑤ 的全部含义。
两个方向互相制约，这是好事
成熟的外壳让自动研究成为可能；
反过来，更聪明的模型会防止外壳被过度工程化——很多复杂设计只是在补模型的洞，洞补上了，设计就该拆掉。
所以这一章讲的不是「怎么写外壳」
写法会过时。不会过时的是那个问题：一个系统凭什么能可靠地把自己改好？
接下来五级阶梯，回答的都是这一个问题。

第二级 · 把上下文当成一本会长大的手册

最朴素的「让它记住教训」是：把经验追加进提示词，让模型定期重写一遍。这个做法会稳定地失败，而且失败方式很有意思——它正是后面所有自动优化都要防的那类病。
ACE 的解法只有一句话：让模型输出「差分」，不要让它输出「全文」
Curator 产出的是一条条带标识符的结构化条目（identifier + description），增删改由外面的确定性逻辑执行。模型负责判断，程序负责落笔——两种病同时被堵住。
Zhang et al., Agentic Context Engineering (ACE), 2025 / ICLR 2026
这一页的方法论价值大于它的技术含量
「让模型提议、让程序执行、让改动可寻址可回退」——这个模式会在第 13、14、17 页原样重现，只不过被改的东西从手册条目换成了外壳源码、再换成优化器本身。
阶梯往上走，这条原则一直不变。

第二级续 · 把「怎么管上下文」和「上下文里是什么」拆开

ACE 优化的是内容：手册里写什么。但决定内容好坏的其实是上一层——用什么办法去检索、筛选、排版。MCE 把这两件事正式分开，于是优化对象从「一段文本」变成了「一个目录加一组算子」。阶梯就是在这里开始向代码倾斜的。
双层优化写成两行式子就是
内层：给定技能 s，找最好的上下文 —— c* = argmax_c J_train(c ; s)
外层：在这个前提下，找最好的技能 —— s* = argmax_s J_val(c* ; s)
内外用不同的数据集，是这套东西不塌掉的关键：内层随便过拟合，外层负责把过拟合的选下去。
Ye et al., Meta Context Engineering (MCE), 2026
为什么说这一页是个转折点
当「技能」被表示成文件系统上的一个目录，而元 Agent 手里只有一套通用的读写工具时，「优化上下文」和「写代码」已经是同一件事了。
再往上一级，被编辑的对象直接换成外壳自己的源码——中间没有台阶，是平的。

第三级 · 工作流：人能手写到什么程度

再往上一级，被优化的是步骤本身：先做什么后做什么、谁调谁、什么时候回头。先看三个由人设计的完整工作流，它们分别把三件不同的事推到了当前的上限。
ScientistOne · 把「可验证」提到中心位置
它的中心约束不是「能不能做完」，而是「每一句话能不能追到证据」。
引用、数值、方法、结论——四类主张全都要挂到一个具体的证据源上，再由一条证据链（Chain-of-Evidence）去审计。
为什么这重要：自动研究最大的失败方式不是做不出来，是做出来一份看起来很像样、但没人能核对的东西。把可追溯性做成硬约束，是目前唯一有效的对策。
Autodata · 自动造题，专造「刚好难」的题
四个角色：出题者造任务，弱解题者和强解题者分别去做，验证判定者裁决。
目标区间很讲究：强的能做出来、弱的做不出来——太简单没信息量，太难没有可学的信号。
但作者给了个降温的评价：合成出来的任务最后只拿去微调弱解题者，更像是一种间接蒸馏，系统整体的上限并没有被自己顶上去，RSI 的味道其实很淡。
三个例子放在一起，正好指出了工作流这一级的天花板
它们都很强，但每一条流水线的形状都是人定的：几个阶段、谁调谁、什么时候回头、什么时候停。系统只在人画好的图上跑，跑得再好也不会自己改这张图。要突破这一点，得让「流水线本身」变成被搜索的对象——下一页。

第三级续 · 让工作流自己被搜出来

既然工作流的好坏可以被评测，那它就可以被搜索。两条路线：ADAS 把 Agent 当成代码去生成，AFlow 把工作流当成图去搜。共同点是——从这里开始，流程图不再是人画的了。
这一级的边界也很清楚：搜出来的还是「流程」，不是「系统」
ADAS 和 AFlow 优化的都是模型被怎么调用——提示怎么组、调几次、结果怎么合。但外壳的其余部分（工具怎么实现、上下文怎么裁、什么算成功、权限到哪）还是人写死的，它们不在搜索空间里。
下一级把整个外壳的源码放进搜索空间——这才是本章真正要讲的那一格。

第四级 · 把外壳的源码本身放进搜索空间

代码是定义程序和系统的通用语言。如果一个模型能优化「执行 Agent 的那段代码」，它能触及的设计空间就比手写提示词大得多——大到几乎没有边界。而空间一大，绝大部分候选都是垃圾，所以这一级真正的技术含量不在「怎么改」，在「凭什么相信这次改对了」。
这三条前提，就是第 13 到 15 页三篇工作各自解决的问题
Self-Harness 主要在解「提得准、判得住」，AHE 主要在解「看得见、归得了因」。它们的具体做法不同，但都在回答同一个问题——怎么让一次自动修改，成为一件可以被检验的事，而不是一次赌博。

Self-Harness：提案 → 验证 → 接受，三段都有讲究

这套流程听上去平平无奇，但每一段都有一个不做就会塌掉的细节。这三个细节比流程本身更值得记。
实验里一个容易被略过的观察
同一套流程在 MiniMax M2.5、Qwen3.5-35B-A3B、GLM-5 上分别跑 Terminal-Bench-2，学出来的指令是「因模型而异」的——不同底座模型需要被提醒的事情不一样。
这说明外壳不是一份放之四海皆准的最佳实践，它是对「这个模型的具体短板」的补偿。换模型，外壳大概率要重学。
Zhang et al., Self-Harness, 2026
作者在这里插了一句很重的话
「如果允许一个程序去编辑操作系统本身，抽象边界就被打破了。」
可编辑面必须被主动设计，而权限控制和安全层必须活在这个回路之外。
这不是一句免责声明——下一页的 AHE 把这句话直接做成了硬约束，而它恰好也是那套方法能拿到干净结果的原因。

AHE 之一：切开可编辑面，然后把剩下的锁死

要让模型改外壳，第一件事是回答：「外壳」到底由哪几块组成，哪几块允许它动。AHE 给出的答案是七个部件——外加一条把剩余部分全部设成只读的分界线。
被封掉的三条路，每一条都是真实会发生的
① 把验证器关了或改松——分数立刻好看　② 偷偷换个更强的模型——涨分与外壳无关　③ 把推理预算调高——花钱买分数
它们都不是「模型学坏了」，而是回路给了它这个口子。把口子焊死之后，剩下的每一分提升都只能来自外壳编辑本身——结论也就有了归因。
第二条硬约束：每一次编辑都得附一份「证据说明」
格式是固定的四段：依据哪条失败证据 · 推断的根因是什么 · 针对性的修法 · 预期影响。
其中「预期影响」必须同时写预计能修好哪些和可能被拖坏哪些。
写完就成了一条可证伪的断言，下一轮的数据直接判它对错。

AHE 之二：真正的瓶颈不是「会不会改」，是「看不看得清」

这套方法的判断是：模型早就有能力写出合理的外壳改动，卡住的地方在于它看不清自己上一轮到底怎么错的。于是重点全放在可观测性上，切成三根支柱。
结果：在 Terminal-Bench-2 上赢过人手工设计的外壳
对比对象包括 OpenCode、Terminus-2、Codex 这些成熟的工程产物——除了最难那一档之外全部超过；同时也超过 ACE 和 TF-GRPO 这类只改上下文或只调权重的路线。这是「模型改外壳」第一次在成熟基准上正面赢过资深工程师的手笔。
Lin et al., Agentic Harness Evolution (AHE), 2026
比赢更值得注意的是：它能迁移
把演化出来的外壳冻住，直接搬到 SWE-bench-verified 上，照样有效。
这说明它学到的不是「怎么在 Terminal-Bench 上拿分」的技巧，而是某种可以带走的工程经验——这一条比排行榜名次重要得多，因为它正面回应了「是不是又在刷榜」这个质疑。

一个反直觉的结果：会改外壳 ≠ 用得上外壳

直觉上「模型越强，这套回路转得越快」。但把能力拆成两个轴分别测，结论完全不是这样——而这个结论直接决定了这套方法今天该怎么用。
发现 A · 写改动这件事，小模型没比大模型差多少
从 9B、32B 一路测到 Opus 4.6，产出有用外壳编辑的能力基本持平。一个 9B 模型写出来的技能文件，在流程结构上和顶配模型写的是同构的。
原因不难理解：外壳改动本质是「把踩过的坑写清楚」，这是个总结性任务，不是推理难题。
Lin et al., Harness Updating Is Not Harness Benefit, 2026
发现 B · 用得上，才是真门槛，而且不是越强越好
要吃到外壳的好处，模型得同时做到两件事：在正确的时机正确地调用那些技能和工具，以及在很长的任务里一直记着遵守这些约定。
太弱的做不到第二条，改了也白改；太强的本来就会，外壳给的边际收益反而小——于是中间那一档收益最大。
推论：提改动和执行任务，本来就该由不同的模型干
既然「写」这一侧对模型能力不敏感，那就用便宜的模型批量产候选；既然「用」这一侧才是瓶颈，那就把强模型的预算留给执行和验证。
这不是省钱技巧，这是这条曲线直接给出的分工方案。

另一种走法：不推理，直接演化

前面几页都是「看日志 → 想清楚 → 改一处」。还有一条完全不同的路子：不要求想明白，只要求大量生成、严格筛选。什么时候该用它有两个判据——搜索空间大且形状怪，以及梯度难求但评估便宜。研究类问题常常正好命中这两条。
这个数字最该被读出的一层意思
整个过程里模型权重一个字节都没变——用的一直是同一个 Claude 3.5 Sonnet。
翻倍的性能全部来自外壳代码被改好了。
这是本章最直接的一个证据：今天可动用的 RSI，主要就在这一层。
演化要防的两件事，前人已经踩过
· 多样性会塌：ShinkaEvolve 用嵌入相似度做新颖性拒绝采样，太像的候选直接不要
· 经验会丢：它另外维护一个记录成功模式的元便签，让后代不用重新踩坑
· 更早的 Promptbreeder 更彻底——连「怎么变异」的提示词自己都在演化
它的适用范围其实很窄
能跑通的地方有个共同点：打分是自动的、快的、明确的——矩阵乘法、GPU kernel、算法竞赛、数据中心调度。
一旦评估变慢、变模糊、或者要靠启发式，这条路立刻失效。再加上算力开销本身就很可观。

第五级 · 不改答案，不改外壳，改「改的那套程序」

阶梯的最后一级，把递归这件事做到了字面意义上：被优化的对象，就是那个负责做优化的程序自己。这是 RSI 定义里那句「用当前的智能改进产生智能的机制」最直接的一次实现。
这一级有一条硬门槛，而且已经被实验撞到过
同一套 STOP：换成 GPT-4 能自我改进，换成 GPT-3.5 和 Mixtral 反而越改越差。
递归结构本身不产生增益。底座模型必须强到「有能力改进一套机制」，这个回路才是正的；否则它只是在放大自己的错误。
Zelikman et al., STOP, 2023 / COLM 2024
和第 16 页那条平线并不矛盾
第 16 页测的是「写出一条有用的外壳编辑」——总结性任务，小模型也做得来。
这一页要的是「改进那个产生编辑的程序」——要理解机制、预判后果、判断哪种搜索策略更好。后者难得多，也就有了门槛。
这一级最该记住的一句话
一旦外壳设计变成了一个可执行的搜索空间，一个足够强的编程 Agent 就能进入人类工程师用的同一片设计空间。
它不需要什么新能力——它只需要那个空间被表示成代码。

再往前一步：把权重也放进同一个回路

到这里为止，模型权重一直是冻着的——所有增益都来自外壳。最后一步是把「改外壳」和「改权重」放进同一个决策回路，每一轮自己决定改哪边。方向上这是完整的 RSI，但目前它也是本章证据最薄的一格。
为什么这一步在概念上很重要
前面所有工作都默认「权重不可动」，于是外壳的天花板就是模型的天花板。一旦权重进了回路，天花板原则上就没有了。
这也正是本章第 2 页说的三种 RSI 形态里，②③ 第一次被接在一起。
但这份证据必须打折看
实验里任务 Agent 用的是 gpt-oss-120b，而元 Agent 和反馈 Agent 用的是 Claude Sonnet 4.6——两侧能力差得太多，涨的分究竟来自「自我改进」还是来自「强模型在指导弱模型」，分不开。对照组也偏弱。
原作者的评价是：方向有意思，证据是暂定的。
Hebbar et al., SIA, 2026
两个真问题还没有答案
· 训练稳定性：外壳每轮都在变，等于给权重训练换了个会动的地面
· Goodhart 效应：两条改进通路都盯着同一个分数，钻空子的机会翻倍

另一条相邻工作（Continual Harness）走得更保守：在长程游戏里一边更新外壳，一边把强教师在低回报轨迹上的判断蒸馏进策略，两者共同学习。

五级阶梯，横着看一遍

级被优化的是什么谁提改动靠什么判断改对了代表工作今天到哪儿了
① 指令提示词 一段自然语言 人 人看结果，凭感觉 提示词工程 大部分技巧已被指令微调吃掉，剩下的价值在「把目标和约束说清楚」
② 结构化上下文 一本条目化的手册 + 取用它的算子 模型提条目，程序负责合并 任务分数，训练集与验证集分开 ACE · MCE 已经工程可用。要防的两个病是上下文坍缩和求简偏好
③ 工作流 步骤图：几个阶段、谁调谁、何时回头 元 Agent 写代码 / MCTS 搜图 基准分数；档案库保留历史最优 AI Scientist · ADAS · AFlow 搜出来的工作流已能赢过人手写的。但外壳的其余部分还在搜索空间之外
④ 外壳代码 执行系统本身的源码，七个可编辑部件 编程 Agent 读日志、提 diff 练手集 + 留出集双回归，都不退步才收 Self-Harness · AHE · DGM 本章重点。已在成熟基准上赢过人设计的外壳，且冻结后能跨基准迁移
⑤ 优化器代码 那个负责做改进的程序自己 上一版的自己 元效用：在一批任务上平均「它改得有多好」 STOP · Meta-Harness 可行，但对底座模型有硬门槛——模型不够强时，递归会把错误一起放大
纵向看，有三件事从头到尾没变过
① 模型提议，程序执行——从 ACE 的条目合并到 AHE 的 diff 落盘，落笔那一下始终不交给模型
② 改动要小、要可寻址、要能撤——大重写在每一级都是错的
③ 判据必须在回路外——这一条在下半章会变成最大的那个瓶颈
横向看，越往下走，「谁在改」这个问题越有意思
①②③ 级里，人还是那个定框架的人；④ 级开始，框架里的每一块都成了变量；⑤ 级连「怎么改框架」也成了变量。
但要注意：到 ⑤ 为止，被改的东西全部还在模型外面。权重那一步（第 19 页）刚起步，且证据薄弱。
换句话说，今天真实存在的 RSI，边界就画在这里。

卡在哪：七个瓶颈，各自挂在回路的哪一段

前面十几页讲的是「已经能做到什么」。接下来五页讲反面。把七个公认的瓶颈挂回第 12 页那个回路上，会发现它们并不是七个孤立的难题——它们全部集中在两个位置。

瓶颈之首：评判器又弱又模糊

这套回路在「指标可测且客观」的地方转得最好——和强化学习能起效的条件是同一条。而它转不动的地方，原因也永远是同一个：没有人能写出一个函数，告诉系统这次做得好不好。
回路转得动的那一侧
共同点：判据是程序，不是人。
· 单元测试过不过
· 编译器报不报错
· kernel 算得对不对、比基线快多少
· 算法竞赛的提交判定
· 数据中心调度的成本数字

这些地方今天已经能自动跑几百上千轮，而且分数是可信的。第 17 页那些翻倍的数字，全部来自这一侧。
回路转不动的那一侧
共同点：判据本身就是研究对象。
· 这个问题值不值得做
· 这个实验设计得对不对
· 这个反常结果是噪声还是线索
· 这段代码三年后好不好维护
· 这篇论文有没有真正的贡献

「研究品味」不是一种可以打分的能力，它混着问题框定、实验设计、和「哪个意外值得追下去」的判断。
于是有了一个很实在的推论
「可验证的边界」往外挪一寸，这套回路的适用面就大一片。
所以真正值钱的工作往往不是把 Agent 调得更聪明，而是给一类原本靠人判的事，造出一个可信的自动判据。
而且弱判据不是「差一点」，是会被主动利用
在一个会持续优化自己的回路里，判据的每一个漏洞都会被系统性地找到并放大——这不是模型学坏了，这是优化的定义。
下一页专门讲这件事。
这也解释了为什么 ④ 级做得比 ⑤ 级实在
改外壳代码，判据可以是「基准分数 + 留出集不退步」——虽然粗糙，但客观。
改优化器，判据变成「这个改进器有多能改」，它本身就是一个需要被估计的量，噪声大得多。

钻空子：为什么它在自我改进的回路里格外危险

单次任务里钻空子只是一次失败，改了就好。但在一个会把「涨分的改动」保留下来的回路里，钻空子的收益会被复利。每一轮它都比老实做事更划算——于是它一定会被找到。
你把什么当判据它会怎么钻为什么在回路里更严重
单元测试写出刚好让这些测试通过的代码；或者直接改测试、跳过测试、给断言加宽松条件过拟合测试的外壳会被保留下来当作父代，后代继承这个策略
模型评委学会这个评委的偏好：更长、更自信、格式更漂亮、带上它喜欢的关键词评委的偏好是稳定的，所以针对它的技巧可以被稳定地积累
基准分数利用基准本身的规律：题目分布、答案格式、评分脚本的边界情况分数照涨，但换个基准就原形毕露——第 15 页那个迁移实验正是为了排除这种情况
「实验成功了」在噪声结果上宣布成功、挑对自己有利的那次运行、用一堆参数把数字凑到好看没有外部核对时，系统会持续说服自己在进步——下一页把这类失败单独拆开讲
唯一有效的结构性对策：把判据挪到回路外面
评判器和权限控制，都不应该待在那个演化外壳的回路里。再配上三样东西：留出测试（防过拟合）、轨迹审计（防「结果对但过程是假的」）、以及在真正重要的决策点上让人过一遍。
这不是加一层保险，这是让「分数上涨」这件事重新变得有意义的前提。
第 14 页那张图，现在可以重新读一遍
AHE 把运行记录、追踪器、验证器、模型配置全部设成只读，不是出于洁癖——那正是这一页说的「把判据挪出回路」的一次具体实现。
口子焊死之后，「关掉验证器」「换个更强的模型」「加大推理预算」这三条最省事的路一次性消失，剩下的涨分才可归因。

另外三个瓶颈：失败没留住、候选长一个样、长期账算不出来

这三个不像评判器那样显眼，但它们决定的是回路能不能一直转下去——前者决定天花板，这三个决定衰减速度。
负结果没被留住
公开文献天然偏向成功案例，模型也就跟着不擅长放弃一个假设——它更容易再试一次，而不是判断这条路本来就不通。

作者的建议很具体：一个研究外壳应该让失败的尝试很容易被保存下来。

因为从失败里学习，是缩小任务搜索空间最有效的办法——「这条路走不通」排除的分支，比「这条路走通了」多得多。
多样性坍缩
回路跑几轮之后，几十个候选会塌成同一个解的若干变体。因为每一轮都在当前评判器下选最优，而最优的邻域是自我强化的。

对开放式研究尤其致命：真正好的路子，在早期用当前的评判器去看，往往比平庸的路子分数更低。

第 17 页 ShinkaEvolve 的新颖性拒绝采样、DGM 按子代数降权，都是在硬顶着这件事。
长期价值算不出来
沙盒里的可验证奖励几乎捕捉不到这些东西：
· 可维护性
· 责任边界清不清楚
· 以后迁移的成本
· 向后兼容
· 将来调试这段代码的负担

而这些恰恰是真实工程里决定成败的部分。一个在沙盒里刷到很高分的外壳，完全可能在真实系统里是负资产。
还有第四个，但它的性质不太一样：上下文与记忆的生命周期
今天的做法是把记忆当成一个外挂的软件模块——存进去、检索回来、拼进提示词。它能用，但它是个补丁：什么该记、什么该忘、什么时候该主动回想，全靠外面写死的规则。
作者在这里下了一个明确判断：「上下文工程将会、也应该成为智能的核心组成部分，而不是停留在软件系统层。」——换句话说，这一格的最终解法不在外壳里，它迟早要回到模型内部去。

把它放去做真研究：六种失败模式

上面的瓶颈是分析出来的。有一项工作是直接把它放去做真研究然后记录下发生了什么：极简脚手架（只有读文件、写文件、检索、列目录四个工具），三个领域（世界模型、多智能体强化学习、AI 安全与对齐），每个领域给 45–50 篇种子文献。
① 倒向训练数据里的默认答案
用已经过时的库和命令，给出的假设没有基于眼前这个仓库的实际情况。它写的是「一般来说该怎么做」，不是「这里该怎么做」。
② 执行压力下的实现漂移
一遇阻力就悄悄退回到更简单、更常见的解法，而最初那个真正想验证的设计被丢掉了。最后跑通的不是当初要做的实验。
③ 记忆与上下文退化
任务一长，早期的约束、已经排除的分支、之前定下的口径，会慢慢从上下文里消失。然后它开始重复做已经做过的事。
④ 过度乐观
在有噪声甚至已经失败的实验上宣布成功。文献里给了两个很传神的说法：「p-hacking 与 eureka-ing」，以及「数值胶带」——把数字粘到好看为止。
⑤ 领域直觉不足
预判一个实现要花多大力气、判断一个结果可不可信、知道哪些 baseline 是必须对比的——这些是隐性手艺，不写在论文里，也就学不到。
⑥ 科学品味弱
代码能跑，实验有结果，图也画得漂亮，但它回答的是一个错的问题。
这是六条里最难自动检测的一条——因为没有任何自动判据会报错。
最终数字：一整套流程跑下来的产出
生成的大量想法里，只有 4 个通过了人类专家的筛选、进入完整流程；其中只有 1 个被真正执行成了一篇论文。
把这个数字和第 17 页那些翻倍的基准成绩放在一起看，本章的结论就完整了——在有自动判据的地方，自我改进已经是可用的工程；在没有自动判据的地方，它离「能自己做研究」还很远。而这两句话之间的距离，就是第 22 页那个瓶颈。

拿什么衡量进展：一条最值得记的曲线

RE-Bench 用 7 个开放式机器学习研究工程环境，请 61 位专家做了 71 次八小时尝试，再和 Agent 对比。结论不是「谁更强」，而是「在多长的时间预算下谁更强」——这条曲线比任何单个分数都更能说明今天的位置。
这条曲线的含义：今天缺的不是「聪明」，是「跑得久」
2 小时预算下 Agent 得分是人的 4 倍；到 8 小时和 32 小时，人全部反超。短预算里 Agent 大幅领先，说明单步质量和吞吐都不是问题。人在长预算上反超，说明差距全在长程能力——保持方向、记住排除过的分支、判断什么时候该放弃重来。而这几样恰好就是第 21 到 24 页那些瓶颈，也恰好就是外壳这一层要解决的东西。

人的位置：往上挪一层，而不是退出

这套回路每往前一步，人手工干的活就少一块。但「少干一块」和「不参与」是两件完全不同的事——前面所有能跑起来的系统，都有人在某个位置上定住了那些回路自己定不了的东西。
如果要把这一章变成一份可以持续核对的东西，接下来几年值得盯的是这六件事——每一件都有明确的观察对象，而且都会给出「是」或「否」。
盯什么看到什么算「往前走了」看到什么算「警报」
「可验证」的边界有没有外移原本必须人判的一类事，出现了可信的自动判据大家改用更容易刷的判据来换取更好看的曲线
失败有没有被系统性地留住失败轨迹和「这条路不通」进了可检索的长期存储，并被后续引用日志只留最近一轮，或只留成功的那些
演化出来的外壳能不能迁移冻结之后换个没见过的基准仍然有效（已有第一个正例）换基准就掉回原点 —— 说明学到的是刷分技巧
「会改」与「用得上」两条曲线用得上那条的峰值往强模型一侧移动，或整体抬高两条都平了 —— 说明外壳这一层的红利吃完了
权重进回路的干净证据出现不依赖「强模型指导弱模型」的自我改进结果继续用能力不对等的组件互相评估，涨分无法归因
判据和权限在回路的哪一侧始终只读，并配有留出测试、轨迹审计、关键点人审被挪进回路内 —— 这是本章列出的所有信号里最危险的一个

这一章的落点

① 今天真实存在的 RSI，在外壳层
不是模型改自己的权重，是模型改包在自己外面那套系统的源码。

机制很朴素：跑一批任务 → 定位根因 → 提一处改动 → 双回归验证 → 接受或回退。被改的是七个部件：系统提示词、工具描述、工具实现、中间件、技能、子 Agent 配置、长期记忆。

DGM 那组数字（同一个模型，SWE-bench 20%→50%）是这一条最直接的证据。
② 这条回路的上限，由评判器决定
不由模型有多聪明决定。

有自动判据的地方，它已经是可用的工程，成绩能翻倍；
没有自动判据的地方，一整套自动研究流程跑下来，专家筛完只剩 4 个想法值得做，最后只有 1 个真的做成了。

这两句话之间的距离，就是这一章全部的未解问题。
③ 会改，和用得上，是两件事
写出一条有用的外壳改动——9B 模型和顶配模型差不多，因为那是个总结任务。

用得上改好的外壳——需要在正确时机调用工具，还要在很长的任务里一直守着约定，这一条是倒 U，中档模型收益最大。

所以合理的分工是：便宜的模型批量提案，贵的预算留给执行和验证。
④ 判据和权限必须待在回路外面
这不是一条安全条款，这是让「分数上涨」这件事重新有意义的前提。
把验证器、追踪器、运行记录、模型配置设成只读之后，「关掉验证」「换个强模型」「加大预算」这三条捷径一次性消失——剩下的每一分提升，才真的来自外壳被改好了。
⑤ 人往上挪，不是退出
回路能自己定的东西越来越多，但它永远定不了「什么算成功」和「什么不许碰」。
人的位置从「逐条审改动」挪到「设计监督点」——而监督点是要提前设计的，不是出事之后补的。
如果你现在正在做一个 Agent 系统，这一章能直接拿走三件事
① 把状态赶出对话，落到文件系统上——不落盘的东西没法被下一轮引用，也没法被任何人检查，更谈不上被自动改进。
② 每一次改动都配一条可证伪的预测，外加一个留出集——「我改这里是因为 X，预计修好 A、可能拖坏 B」，下一轮直接判它对错。
③ 把判据和权限锁成只读——不管你有没有打算做自动优化，这一条现在做，成本最低。
