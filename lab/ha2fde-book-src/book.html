3第一章 · 破冰
第 1 章 · 它们跟 ChatGPT 有啥不一样？

破误解：Agent 是"干活"，不是"回答"

💬 入门者原话："我用过 ChatGPT，这些 Agent 不就是更强的聊天机器人吗？"
直接回答：不是。ChatGPT 给你一段"回答"，Agent 替你"把活干完"——读文件、改代码、跑命令、调工具，从头做到尾。
聊天机器人（ChatGPT 类）AI Agent（Claude Code 类）
你给它一个问题一个任务
它给你一段文字回答干完的结果（文件改好了 / 命令跑完了）
动手能力没有，只能说有：读写文件、跑命令、调工具
工作方式一问一答思考→行动→看结果→再思考，循环到干完
一句话顾问实习生
✅ 你现在可以做什么：回想一件你最近想让电脑"自己干完"的杂活——那就是 Agent 的用武之地。

第 1 章 · 它们跟 ChatGPT 有啥不一样？

Agent 的三要素：有手、有脑、有循环

💬 入门者原话："那它凭什么能'干活'？"
直接回答：它比聊天机器人多了三样东西：手（工具）、脑（大模型）、循环（干一步看一步）。

一个任务："帮我把这堆文件整理好"

↓

🧠 有脑

大模型想"下一步该干嘛"

↓

✋ 有手

读写文件 / 跑命令 / 调工具

↓

🔁 有循环

看结果 → 不对就换法子 → 再干，直到干完汇报

对比一下

聊天机器人
只有脑，没有手和循环

AI Agent
脑 + 手 + 循环，三样齐全才能"干活"

✅ 你现在可以做什么：记住口诀——"有手、有脑、有循环"，后面所有工具都是这三样的不同包装。

9第一章 · 破冰
第 5 章 · 大脑从哪来（云端）

云端的三种"买脑"方式：专卖店 / 超市 / 全球代购

💬 入门者原话："都说要配 API，API 到底去哪买？"
直接回答：云端大脑有三个"货架"，区别不在"国内 / 国外"四个字，而在你能买到什么模型、谁开票合规、网络稳不稳：① 厂商直供＝单点直连、最透明；② 国内云聚合＝一个 Key 买齐多家国产模型；③ 全球中转网关＝一个 Key 用上 Claude / GPT / Llama 等全球模型。

形态一 · 厂商直供（专卖店）

单点直连，一家一个 Key

  • DeepSeek / Kimi（月之暗面）
  • GLM（智谱）/ MiniMax …
  • 每家用各家的 Key
  • 最透明、最可控、可精挑模型

形态二 · 国内云聚合（超市）

一个 Key 买齐多家国产模型

  • 火山引擎方舟（字节）
  • 阿里云百炼（通义）
  • 统一接口、一个 Key 管多种
  • 合规稳、国内网络快，但仍是国产模型

形态三 · 全球中转网关（代购）

一个 Key 接全球几百个模型

  • OpenRouter 等
  • 能用上国内拿不到的 Claude/GPT/Llama
  • 统一计费、自动路由
  • 代价：走中转、延迟与合规要权衡
三家都有"免费入口"：注册赠送 / 免费额度 / 免费模型（额度以各平台官方为准）。记住：形态二 ≠ 形态三——前者只聚国产模型，后者才通向全球模型。
✅ 你现在可以做什么：先不用注册任何账号——看完第 11 章"免费资源地图"再决定办哪家的"卡"。

第 5 章 · 大脑从哪来（云端）

三个名词：API Key、Base URL、模型名

💬 入门者原话："教程里老出现 API Key、Base URL，都是啥意思？"
直接回答：记住三句话：API Key 是付款凭证，Base URL 是接口地址，模型名是选哪个大脑。把用云端大脑想成"打电话叫外援"。

📞 Base URL

= 电话号码（打给哪家平台）

厂商的 / 云平台的 / OpenRouter 的，各不一样

🔑 API Key

= 话费账户（付款凭证）

谁拿到都能花你的钱 → 别泄露、别发群聊

🧠 模型名

= 点名要哪个大脑接电话

同一家店里也有很多模型可选

⇒ 任何 Agent 工具配置云端大脑，填的都是这三样。看到教程先找这三个词，找到就看得懂。
✅ 你现在可以做什么：以后看到任何配置教程，先找这三个词——找到就看得懂。

第 6 章 · 自己搭大脑：本地运行大模型（重点）

把大脑装在自己电脑上：为什么有人要这么干

💬 入门者原话："模型还能装在我自己电脑上？图什么？"

本地跑的好处要付的代价
隐私：数据不出本机要硬件：内存 / 显存决定能跑多大的模型

离线：断网也能用模型文件占硬盘（几个 GB 起）
完全可控：想换就换、想删就删第一次要下载模型，要等

💬 入门者原话："我这台电脑跑得动吗？要去哪下模型？"
直接回答：重点看"主流能跑的"——高配 Mac / 高配显卡的个人电脑，或企业的华为昇腾 NPU，都能跑实用的中大模型；纯 CPU 小模型只适合尝鲜，不推荐做主力。
① 配置三档（个人 / 企业视角）
档位你的硬件能跑什么

第 6 章 · 自己搭大脑：本地运行大模型（重点）

个人可选模型清单 + 本地大脑接进壳里

💬 入门者原话："模型名字一大堆，我下哪个？本地大脑能给那些 Agent 工具用吗？"

     你看到的                机器看到的
 ┌────────────┐      ┌───────────────────────┐
 │ "猫"        │  →   │ 231, 140, 171  (字节)  │
 │ 一张猫的照片 │  →   │ 255, 200, 180, 45, …  │

 └────────────┘      └───────────────────────┘
        机器世界里只有一种数据：数字

第 2 章 · 上

编号不是意思：one-hot 的死胡同

① 你可能的疑惑"词变数字还不简单？给每个词编个号不就行了。"
② 点破卡点编号里没有"意思"。"猫"是 3 号、"狗"是 4 号，3 和 4 挨得近，不代表猫和狗像。机器拿到的只有"一样 / 不一样"，永远算不出"有多像"。
 词表 = ["我", "爱", "猫", "狗", …]   共 50000 个词

 "猫" → [0, 0, 1, 0, 0, 0, …, 0]   ← 第 3 位是 1，其余全 0
 "狗" → [0, 0, 0, 1, 0, 0, …, 0]   ← 第 4 位是 1，其余全 0

 这只是一个"位置号码"：
   "猫"和"狗"的距离  ==  "猫"和"汽车"的距离
   → 语义信息：零
一句话说清one-hot 让每个词有了数字表示，但表示里不含语义——这正是下一个瓶颈的入口。
④ 数据流 · Python
vocab = ["我", "爱", "猫", "狗"]
onehot = {w: [int(i == j) for i in range(4)]
          for j, w in enumerate(vocab)}
print(onehot["猫"])  # [0, 0, 1, 0] 只是位置号

embedding：词义 = 向量

① 你可能的疑惑"那怎么让数字带上意思？"
② 点破卡点需要的不是"编号"，而是"坐标"：让意思相近的词，坐标也相近——"像不像"从此变成"距离近不近"，机器就能算了。
        语义空间（几百维，压成 2 维示意）
   高 │
 王   │     ●国王            ●女王
 室   │            ●男人   ●女人
      │
 水   │          ●苹果(水果)
 果   │    ●香蕉
      └──────────────────────────→

 关键性质：方向也带含义   国王 − 男人 + 女人 ≈ 女王
 坐标不用人设计：读够多文本，"上下文相似的词"会自动凑到一块儿
一句话说清embedding 解决"数字没有语义"——词义被编码成向量，语义相近则向量相近。（动手：附录脚本 1 embedding_demo.py）

 ① 组合爆炸：前 3 个词的组合数 = 词表³，表根本装不下
 ② 没有泛化："他想吃 ___"表里没见过 → 直接抓瞎
   （明明和"我想吃"很像，但表格不懂"很像"）

 RNN 顺序读：

第 4 章 · 答案为何每次不同

同一个问题隔一分钟再问，答案怎么变了？

模型不是"算出唯一答案"，而是按概率抽样——每次都在掷一个加权骰子。

 模型为下一个 token 给出概率分布:
   的:0.50   是:0.20   很:0.10   真:0.05   ...长尾...
        |
        v  [temperature] 温度缩放
   T -> 0 : 分布变尖, 最大者通吃 -> 几乎总选 "的"  (稳定保守)
   T = 0.9: 分布拉平, 小概率词也有出头之日         (发散多样)
        |
        v  [top_p = 0.9] 截断
   只保留累计概率前 90% 的候选池: {的, 是, 很}
        |
        v  [随机采样] 本轮吐出: "很"
        |
        v  [max_new_tokens] 控制这个循环最多再走多少步

要点

  1. temperature：低 → 稳定保守（要事实、要格式时调低）；高 → 发散多样（要创意时调高）
  2. top_p：只在累计概率前 p 的候选池里抽，砍掉长尾烂词，多样但不离谱
  3. max_new_tokens：生成长度上限，防止无限生成，也控制成本

安全：Agent 特有的攻击面

你可能的疑惑传统应用安全做得很多了，Agent 有什么新风险？

Agent 会"读指令、做决策、动手执行"——恶意内容只要能影响它的判断，就能让它替你犯错。

攻击面 1：提示注入（Prompt Injection）
  恶意指令藏在用户输入 / 网页 / 文档 / 邮件里
  ┌─────────┐  读取  ┌───────────────────┐
  │ 恶意网页 │ ─────► │ Agent 把隐藏指令    │
  │"忽略之前指令…"│    │ 当成任务执行       │
  └─────────┘        └───────────────────┘

攻击面 2：越权执行
  Agent 拿着过大的权限，一个误判 = 一次生产事故
  （能删库的工具，就别怪它真删）

攻击面 3：数据泄露
  敏感数据被读进上下文 → 随工具调用 / 外部 API 传出去
落地提示：把 Agent 当成"一个会被骗、但手很快的新员工"来设计权限，而不是当成一段确定性的代码。

安全：四道防线（纵深防御）

你可能的疑惑攻击面防不完，从哪几件事做起？

纵深防御——任何单点被突破，还有下一道。

防线做什么防什么
最小权限每个工具只授予完成任务必需的最小权限（只读优先，写操作收窄到具体对象）越权执行
沙箱隔离代码执行、文件操作放在隔离环境（容器 / 受限目录），与生产环境隔开注入后的破坏扩散
工具白名单只能调用登记过的工具与参数范围，未登记一律拒绝注入诱导的任意调用
执行前确认高危 / 不可逆操作（删、改、发、付）必须经确认后才执行一切"手快"事故

兜底原则：敏感数据不传出——进上下文的敏感字段脱敏，出 Agent 的调用做内容检查。

落地提示：四道防线中"执行前确认"成本最低、收益最大，第一天就该有。

治理：让 Agent 合规可控

你可能的疑惑安全和治理听起来都像"管 Agent"，分工是什么？

安全管"防住"（不让坏事发生），治理管"管住"（发生的事可回查、可审批、可算账）。

治理四件事内容
审计日志谁触发、调了什么工具、输入输出、结果如何——全量留痕可回查
审批流高危操作需人批准，分级审批、与工单系统打通
合规要求数据处理符合监管与内部制度（GDPR 类法规一句话：涉及个人数据即受约束）
成本治理token 用量监控、消费上限、异常告警
维度安全治理
目标防住：阻止坏事发生管住：发生的事可控可溯
视角攻击者视角管理者视角
手段沙箱、白名单、最小权限审计、审批、配额
失效后果被注入、越权、泄露说不清、算不清、停不下
落地提示：审计日志是治理的地基——没有留痕，审批、合规、成本全是空中楼阁。

一个 LLM 是怎么炼成的

从一堆原始文本，到一个会思考、懂配合的助手，要走三道工序。

STEP 1

预训练 Pretrain

在海量文本上做 next-token 预测，炼出"博学但口无遮拦"的基座模型。

STEP 2

SFT 教会它听懂指令，RLHF / DPO 让它更有用、更讨喜、更安全。

STEP 3

推理增强 Reasoning

用思维链和强化学习，赋予模型"想几步再答"的深度推理能力。

Transformer：为规模化而生的架构

核心机制

Self-Attention 自注意力

序列里每个词都能直接"看见"其他所有词，长程依赖一步到位，天然适合大规模并行计算。

多头注意力 + 前馈网络

多头捕捉多种关系，LayerNorm 与残差连接保证深层网络可训练；GPT 系采用 Decoder-only 结构。

它把计算的并行度拉满 —— 算力砸得越多，模型长得越快。这正是苦涩教训所预言的"能吃掉海量算力的通用方法"。

02 · Chat

对齐（上）：SFT，从"会续写"到"会对话"

  • 问题：基座模型只会"接着往下编"，不会问答、不懂配合，像个博学的"接话机器"。
  • 做法：用高质量的指令–回答配对数据做监督微调（Supervised Fine-Tuning）。
  • 效果：模型学会听懂指令、扮演"助手"角色，输出更贴合人类期望的格式与语气。
  • 经验：数据质量远重于数量 —— LIMA 实验证明，几千条精选数据即可显著对齐。

冷启动

# -*- coding: utf-8 -*-
"""
ngram_demo.py —— 演示"统计造句"：n-gram 是怎么学说话的（对应 PPT 第 3 章）。

做法：
  1. 统计文本里"前 N-1 个字之后，最常接哪个字"（数频次，不做任何理解）
  2. 生成时不断查表、按频次抽下一个字 —— 得到"模仿腔"文本

你会看到：腔调很像原文，但细看全是破绽 —— 这就是"只会记词组"的上限。

运行：python ngram_demo.py   （纯标准库，无需安装任何东西）
"""

import random
from collections import defaultdict

# 一段"有腔调"的样本文本（武侠风）。换成任何文本都能模仿。
TEXT = """
江湖夜雨，孤灯如豆。少年仗剑而立，衣袂猎猎作响。远处传来一阵箫声，
箫声幽幽，如泣如诉。少年收剑入鞘，循声而去。山道蜿蜒，松涛阵阵，
一轮冷月悬于绝壁之上。少年抬头望月，忽见一道白影掠过山巅，快如闪电。
少年提气纵身，追了上去。白影忽隐忽现，箫声忽远忽近。少年追到断崖边，
只见云雾翻腾，深不见底。箫声戛然而止。少年仗剑四顾，松风依旧，冷月无声。
"""

N = 3  # 用前 2 个字预测第 3 个字（3-gram）


def train(text, n):
    """统计：前 n-1 个字 -> 下一个字的频次表。"""
    table = defaultdict(lambda: defaultdict(int))
    chars = [c for c in text if not c.isspace()]
    for i in range(len(chars) - n + 1):
        prefix = "".join(chars[i : i + n - 1])
        nxt = chars[i + n - 1]
        table[prefix][nxt] += 1
    return table


def generate(table, n, seed, length=60):
    """从种子开头出发，每次查表、按频次随机抽下一个字。"""
    out = list(seed)
    for _ in range(length):
        prefix = "".join(out[-(n - 1):])
        candidates = table.get(prefix)
        if not candidates:  # 表里没有这个前文 —— 抓瞎，随机挑一个字续命
            nxt = random.choice(list("的一是不了我人在他有上"))
        else:
            chars, weights = zip(*candidates.items())
            nxt = random.choices(chars, weights=weights)[0]
        out.append(nxt)
    return "".join(out)


def main():
    random.seed(42)
    table = train(TEXT, N)

    print("=" * 64)
    print(f"第 1 步：统计表长这样（{N-1} 个字 -> 下一个字的频次）")
    print("=" * 64)
    for prefix in ["少年仗", "年仗剑", "箫声", "月"]:
        key = prefix[-(N - 1):]
        if key in table:
            items = sorted(table[key].items(), key=lambda kv: -kv[1])
            top = "  ".join(f"{c}×{n}" for c, n in items[:5])
            print(f"  「{key}」之后接过 → {top}")

    print("\n" + "=" * 64)
    print("第 2 步：查表生成 3 段「模仿腔」文本")
    print("=" * 64)
    for i, seed in enumerate(["少年仗剑", "箫声幽幽", "冷月无声"], 1):
        print(f"\n【生成 {i}】（开头：{seed}）")
        print("  " + generate(table, N, seed))

    print("\n" + "=" * 64)
    print("观察：字都是原文里的字，腔调也像 —— 但句子讲不通。")
    print("这就是 n-gram 的天花板：只会「背词组」，从不「懂意思」。")
    print("而且换一段它没背过的前文，它就只能瞎接。")


if __name__ == "__main__":
    main()

def build_vectors(corpus, window):
    counts = {}
    for line in corpus.strip().splitlines():
        words = line.split()
        for i, w in enumerate(words):
            vec = counts.setdefault(w, {})
            for j in range(max(0, i - window), min(len(words), i + window + 1)):
                if i != j:
                    ctx = words[j]
                    vec[ctx] = vec.get(ctx, 0) + 1
    return counts


def cosine(v1, v2):
    """余弦相似度：两个向量"方向"有多像（-1 ~ 1，越接近 1 越像）。"""
    dot = sum(v * v2.get(k, 0) for k, v in v1.items())
    n1 = sqrt(sum(v * v for v in v1.values()))
    n2 = sqrt(sum(v * v for v in v2.values()))
    return dot / (n1 * n2) if n1 and n2 else 0.0

# -*- coding: utf-8 -*-
"""
tiny_lm_train_demo.py —— 亲手训练一个极小的语言模型（对应 PPT 第 3~9 章）。

它做的事情，和训练 GPT 在结构上一模一样：
  1. 任务：给定前面几个字，预测下一个字（语言模型的主线任务）
  2. 模型：字 -> 向量(embedding) -> 若干层加权变换 -> 每个候选字的概率
  3. 训练：预测错了就算"错多少"(loss)，再微调权重，重复几千次
  4. 看 loss 一路下降，再让它续写 —— 从乱码长成"有点像"

规模：约 4 万个参数（GPT 是千亿级，但流程相同），普通 CPU 几秒跑完。

运行：python tiny_lm_train_demo.py   （需要 numpy：pip install numpy）
"""

import numpy as np

# ---------- 训练文本：几首古诗（字符级建模，字就是"词"） ----------
TEXT = """
床前明月光，疑是地上霜。举头望明月，低头思故乡。
春眠不觉晓，处处闻啼鸟。夜来风雨声，花落知多少。
白日依山尽，黄河入海流。欲穷千里目，更上一层楼。
红豆生南国，春来发几枝。愿君多采撷，此物最相思。
空山不见人，但闻人语响。返景入深林，复照青苔上。
千山鸟飞绝，万径人踪灭。孤舟蓑笠翁，独钓寒江雪。
"""

CTX = 8     # 用前 8 个字预测下一个字
DIM = 24    # 每个字的向量维度（embedding）
HID = 128   # 隐藏层大小
STEPS = 3000
BATCH = 32
LR = 0.3

rng = np.random.default_rng(42)

# ---------- 字表 ----------
chars = sorted(set(TEXT))
V = len(chars)
c2i = {c: i for i, c in enumerate(chars)}
i2c = dict(enumerate(chars))
data = np.array([c2i[c] for c in TEXT])

# ---------- 模型参数（随机初始化） ----------
E = rng.normal(0, 0.1, (V, DIM))            # 字向量表
W1 = rng.normal(0, 0.1, (CTX * DIM, HID))   # 隐藏层权重
b1 = np.zeros(HID)
W2 = rng.normal(0, 0.1, (HID, V))           # 输出层权重
b2 = np.zeros(V)

n_params = sum(p.size for p in [E, W1, b1, W2, b2])
print(f"字表大小 {V}，模型参数 {n_params:,} 个（GPT 是千亿级，流程相同）\n")


def forward(X):
    """X: (batch, CTX) 个字 -> 每个候选字的概率。"""
    emb = E[X].reshape(len(X), -1)       # 字 -> 向量，拼成一长条
    h = np.tanh(emb @ W1 + b1)           # 一层加权变换
    z = h @ W2 + b2                      # 再一层 -> 每个候选字的得分
    z -= z.max(axis=1, keepdims=True)    # 数值稳定
    p = np.exp(z)
    p /= p.sum(axis=1, keepdims=True)    # 得分 -> 概率
    return emb, h, p


def sample_batch():
    ix = rng.integers(CTX, len(data), size=BATCH)
    X = np.stack([data[i - CTX : i] for i in ix])
    return X, data[ix]


# ---------- 生成：给它一个开头，让它自己往下续 ----------
def generate(seed_text, length=40, temperature=0.8):
    ctx = ([0] * CTX + [c2i.get(c, 0) for c in seed_text])[-CTX:]  # 不足 8 个字前面补 0
    out = list(seed_text)
    for _ in range(length):
        X = np.array([ctx[-CTX:]])
        _, _, p = forward(X)
        p = p[0] ** (1 / temperature)
        p /= p.sum()
        nxt = rng.choice(V, p=p)
        out.append(i2c[nxt])
        ctx.append(nxt)
    return "".join(out)


# ---------- 训练前：模型还是"白纸"，续写是乱码 ----------
print("【训练前】让它续写「床前明月光」—— 纯随机，是乱码：")
print("   " + generate("床前明月光", 20) + "\n")

# ---------- 训练：就是不断重复"预测 -> 算错多少 -> 微调权重" ----------
print("开始训练（训练 = 不断把预测错误往下压）：")
for step in range(1, STEPS + 1):
    X, Y = sample_batch()
    emb, h, p = forward(X)

    loss = -np.log(p[np.arange(len(X)), Y]).mean()   # 预测错多少

    # 反向算"每个参数该往哪调"（梯度），再微调
    dz = p
    dz[np.arange(len(X)), Y] -= 1      # 正确答案那一维，误差最大
    dz /= len(X)
    dW2, db2 = h.T @ dz, dz.sum(axis=0)
    dh = (dz @ W2.T) * (1 - h**2)
    dW1, db1 = emb.T @ dh, dh.sum(axis=0)
    demb = (dh @ W1.T).reshape(len(X), CTX, DIM)

    for param, grad in [(W1, dW1), (b1, db1), (W2, dW2), (b2, db2)]:
        param -= LR * grad             # 错了就微调权重
    np.add.at(E, X, -LR * demb)        # 字向量表也一样微调

    if step % 500 == 0 or step == 1:
        print(f"  第 {step:>5} 步   loss = {loss:.3f}")


print("\n【训练后】再让它续写几句（开头是我们给的，后面全是它自己接的）：")
for seed in ["床前明月光", "春眠不觉晓", "白日依山尽", "千山鸟飞绝"]:
    print(f"\n  【{seed} ……】")
    print("   " + generate(seed))

print("\n看到了吗：")
print("  · loss 一路下降 —— “训练”就是在压这个预测错误；")
print("  · 生成的字从乱码变成了有诗的样子 —— 规律是从数据里学出来的，没人教它；")
print("  · 把模型放大到千亿参数、文本换成整个互联网 —— 那就是 GPT 的预训练。")

    history = []

    for i, (u, a) in enumerate(ROUNDS, 1):

            print(f"  [截断] 丢弃最老消息({dropped['role']}): {dropped['content'][:18]}...")
            msgs = [SYSTEM] + history
            text = render(tok, msgs)
            n = len(tok(text).input_ids)
        print(f"  最终送入模型: {n} tokens, system 保留: {msgs[0] == SYSTEM}")

"""
第 7 章: 怎么让它"动手干活"? —— 工具调用 + ReAct 循环
输入: 需要计算的提问(默认 "38乘27再加100是多少?", 可用命令行参数覆盖)
输出: 每轮 Thought / Action / Observation 日志 + 最终回答

依赖: pip install torch transformers
原理: 工具说明写进提示词 -> 模型输出 "Action: 工具(参数)" 或 "Final: 答案"
      -> 程序解析并真正执行 -> 结果以 role=tool 回填 -> 继续循环, 上限 5 轮
说明: 0.5B 小模型不一定每次都遵守格式, 脚本带解析失败兜底; 换更大模型更稳
"""
import sys
import ast
import operator as op
import datetime
# import os; os.environ["HF_ENDPOINT"] = "https://hf-mirror.com"
from transformers import AutoTokenizer, AutoModelForCausalLM

MODEL = "Qwen/Qwen2.5-0.5B-Instruct"
MAX_LOOPS = 5

# ---------------- 工具实现(程序真正执行的部分) ----------------
_OPS = {ast.Add: op.add, ast.Sub: op.sub, ast.Mult: op.mul,
        ast.Div: op.truediv, ast.Pow: op.pow, ast.Mod: op.mod, ast.USub: op.neg}


def safe_eval(expr):
    """只允许四则运算/乘方/取余的安全计算器(不用 eval)"""
    def ev(node):
        if isinstance(node, ast.Expression):
            return ev(node.body)
        if isinstance(node, ast.Constant) and isinstance(node.value, (int, float)):
            return node.value
        if isinstance(node, ast.BinOp) and type(node.op) in _OPS:
            return _OPS[type(node.op)](ev(node.left), ev(node.right))
        if isinstance(node, ast.UnaryOp) and type(node.op) in _OPS:
            return _OPS[type(node.op)](ev(node.operand))
        raise ValueError(f"不支持的表达式: {ast.dump(node)}")
    return ev(ast.parse(expr, mode="eval"))


def calc(expr: str) -> str:
    try:
        return str(safe_eval(expr))
    except Exception as e:
        return f"计算失败: {e}"


def current_date() -> str:
    return datetime.date.today().isoformat()


TOOLS = {"calc": calc, "current_date": current_date}

SYSTEM_PROMPT = """你是一个会使用工具的助手。可用工具：
- calc(expr): 计算器，计算数学表达式，如 calc(38*27+100)
- current_date(): 返回今天的日期

工作方式：每一步你只能输出以下两种格式之一：
1) 需要工具时输出一行： Action: 工具名(参数)
2) 信息足够回答时输出一行： Final: 你的最终答案
不要输出其他内容。"""


def llm(tok, model, messages):
    text = tok.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
    ids = tok(text, return_tensors="pt")
    out = model.generate(**ids, max_new_tokens=120, do_sample=False)
    return tok.decode(out[0][ids.input_ids.shape[1]:], skip_special_tokens=True).strip()


def parse_action(out):
    """从模型输出中解析 Action: name(args), 解析不到返回 None"""
    for line in out.splitlines():
        line = line.strip()
        if line.startswith("Action:"):
            call = line[len("Action:"):].strip()
            name, _, rest = call.partition("(")
            args = rest.rsplit(")", 1)[0].strip().strip("'\"")
            return name.strip(), args
    return None


def main():
    question = sys.argv[1] if len(sys.argv) > 1 else "38乘27再加100是多少？"
    tok = AutoTokenizer.from_pretrained(MODEL)
    model = AutoModelForCausalLM.from_pretrained(MODEL)
    messages = [
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user", "content": question},
    ]
    print(f"问题: {question}\n")

    # ---------------- ReAct 主循环 ----------------
    for step in range(1, MAX_LOOPS + 1):
        out = llm(tok, model, messages)            # Thought
        print(f"--- 第 {step} 轮 ---")
        print(f"模型输出: {out}")

        if "Final:" in out:                      # 决定直接回答
            print(f"\n最终回答: {out.split('Final:')[-1].strip()}")
            return

        parsed = parse_action(out)               # 解析 Action
        if parsed is None:
            print("未解析到 Action, 要求模型按格式重试")
            messages.append({"role": "assistant", "content": out})
            messages.append({"role": "user", "content":
                             "请严格按格式输出: Action: 工具名(参数) 或 Final: 答案"})
            continue

        name, args = parsed
        if name not in TOOLS:
            result = f"未知工具: {name}"
        else:
            result = TOOLS[name](args) if args else TOOLS[name]()
        print(f"执行工具: {name}({args}) -> {result}")

        # Observation: 结果以 role=tool 回填进上下文
        messages.append({"role": "assistant", "content": out})
        messages.append({"role": "tool", "content": f"Observation: {result}"})

    print("\n达到循环上限, 强制结束(防止死循环)")


if __name__ == "__main__":
    main()

  curl http://127.0.0.1:8000/v1/chat/completions -H "Content-Type: application/json" -d "{\"model\":\"qwen\",\"messages\":[{\"role\":\"user\",\"content\":\"你好\"}],\"stream\":true}"

import json

from fastapi import FastAPI
from fastapi.responses import StreamingResponse

from transformers import AutoTokenizer, AutoModelForCausalLM, TextIteratorStreamer

MODEL = "Qwen/Qwen2.5-0.5B-Instruct"

print(f"加载模型 {MODEL} ...")

class ChatRequest(BaseModel):
    model: str = "qwen"
    messages: list
    stream: bool = False
    max_tokens: int = 512
    temperature: float = 0.7


def build_inputs(messages):
    text = tok.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
    return tok(text, return_tensors="pt")


def sse_chunk(content, model_name, finish=False):
    """按 OpenAI 流式格式组装一条 SSE 事件"""
    payload = {
        "id": f"chatcmpl-{uuid.uuid4().hex[:8]}",
        "object": "chat.completion.chunk",
        "created": int(time.time()),
        "model": model_name,
        "choices": [{
            "index": 0,
            "delta": {} if finish else {"content": content},
            "finish_reason": "stop" if finish else None,
        }],
    }
    return f"data: {json.dumps(payload, ensure_ascii=False)}\n\n"


@app.post("/v1/chat/completions")
def chat(req: ChatRequest):
    ids = build_inputs(req.messages)
    do_sample = req.temperature > 0
    gen_kwargs = dict(max_new_tokens=req.max_tokens,
                      do_sample=do_sample,
                      temperature=req.temperature if do_sample else None,
                      top_p=0.9 if do_sample else None)

    if not req.stream:
        out = model.generate(**ids, **gen_kwargs)
        answer = tok.decode(out[0][ids.input_ids.shape[1]:], skip_special_tokens=True)
        return {
            "id": f"chatcmpl-{uuid.uuid4().hex[:8]}",
            "object": "chat.completion",
            "created": int(time.time()),
            "model": req.model,
            "choices": [{
                "index": 0,
                "message": {"role": "assistant", "content": answer},
                "finish_reason": "stop",
            }],
        }

    def stream():
        streamer = TextIteratorStreamer(tok, skip_prompt=True, skip_special_tokens=True)
        kwargs = {**ids, **gen_kwargs, "streamer": streamer}
        Thread(target=model.generate, kwargs=kwargs, daemon=True).start()
        for piece in streamer:                       # 模型每出一个 token
            yield sse_chunk(piece, req.model)        # 就推一条 SSE 事件
        yield sse_chunk("", req.model, finish=True)
        yield "data: [DONE]\n\n"

    return StreamingResponse(stream(), media_type="text/event-stream")

def models():

        for req_model in [MODEL, "qwen"]
    ]}

# -*- coding: utf-8 -*-
"""
sdk_react_demo.py —— 第4章配套脚本：用 SDK 手写 ReAct 循环
=============================================================
用官方 SDK 手写一个 Agent 主循环，内置一个计算器工具。
每轮打印中间过程：模型要调哪个工具 -> 参数是什么 -> 执行结果 -> 回填。
核心结构不到 10 行：发消息+工具描述，有 tool_calls 就执行回填，否则输出。

运行前：pip install openai
接口配置：修改下方 CONFIG 区（base_url 指向任何兼容 Chat Completions 的接口）
"""
import json

from openai import OpenAI

# ============ CONFIG：在这里配置你的接口 ============
BASE_URL = "https://api.openai.com/v1"   # 或本地服务，如 "http://localhost:11434/v1"
API_KEY = "sk-xxx"
MODEL = "gpt-4o-mini"
# ====================================================

TASK = "(128 + 256) * 3 等于多少？算完告诉我结果。"

client = OpenAI(base_url=BASE_URL, api_key=API_KEY)


# ---- 工具 1：计算器（真实执行体）----
def calc(expr: str) -> str:
    try:
        return str(eval(expr, {"__builtins__": {}}, {}))  # demo 用；生产请换安全求值
    except Exception as e:
        return f"计算出错: {e}"


TOOLS = {"calc": calc}

# ---- 工具描述（发给模型的 JSON Schema）----
TOOLS_SCHEMA = [{
    "type": "function",
    "function": {
        "name": "calc",
        "description": "计算一个数学表达式，返回结果字符串",
        "parameters": {
            "type": "object",
            "properties": {"expr": {"type": "string", "description": "如 (128+256)*3"}},
            "required": ["expr"],
        },
    },
}]


def main():
    messages = [{"role": "user", "content": TASK}]
    round_no = 0
    # ============ ReAct 主循环（本脚本唯一的核心） ============
    while True:
        round_no += 1
        print(f"\n----- 第 {round_no} 轮 -----")
        msg = client.chat.completions.create(
            model=MODEL, messages=messages, tools=TOOLS_SCHEMA
        ).choices[0].message
        messages.append(msg)

        if not msg.tool_calls:                      # 没有工具调用 -> 想完了
            print("最终回答：", msg.content)

            args = json.loads(c.function.arguments)

            result = TOOLS[c.function.name](**args)
            print(f"工具执行结果: {result}  -> 回填 messages")
            messages.append({
                "role": "tool", "tool_call_id": c.id, "content": str(result),
            })
        if round_no >= 8:                           # 安全护栏：轮次上限
            print("超过最大轮次，强制结束")
            break
    # ==========================================================


if __name__ == "__main__":
    main()

# -*- coding: utf-8 -*-
"""
langgraph_plan_demo.py —— 第7章配套脚本：用 LangGraph 画一张 Plan-and-Execute 图
===================================================================================
把流程画成图，而不是写 if/else：
    START -> plan（规划：任务拆成步骤）-> act（逐步执行）-> sum（汇总答案）-> END
每个节点是一个普通函数，节点间通过 State 共享数据。
运行时会打印节点流转顺序与最终答案。

运行前：pip install langgraph langchain-openai
接口配置：修改下方 CONFIG 区（ChatOpenAI 的 base_url 指向任何兼容接口）
提示：compile() 时传入 checkpointer 即可获得断点恢复/人审，demo 从简。
"""
import operator
from typing import Annotated, TypedDict

from langchain_openai import ChatOpenAI
from langgraph.graph import END, START, StateGraph

# ============ CONFIG：在这里配置你的接口 ============
BASE_URL = "https://api.openai.com/v1"   # 或本地服务，如 "http://localhost:11434/v1"
API_KEY = "sk-xxx"
MODEL = "gpt-4o-mini"
# ====================================================

TASK = "估算一家 30 人的远程团队一年的协作软件开销，并给出节省建议。"

llm = ChatOpenAI(base_url=BASE_URL, api_key=API_KEY, model=MODEL, temperature=0)


# ---- State：节点之间共享的数据结构（图的"血液"）----
class PlanState(TypedDict):
    task: str
    plan: list[str]                                # 规划出的步骤
    results: Annotated[list[str], operator.add]    # 各步结果（reducer：追加而非覆盖）
    answer: str


# ---- 节点 1：规划 —— 把任务拆成可执行的步骤列表 ----
def plan_node(state: PlanState):
    print(f"\n[NODE plan] 进入规划，任务：{state['task']}")
    resp = llm.invoke(
        "把任务拆成 3 个有序步骤，每步一行，只输出步骤本身。\n任务：" + state["task"]
    )
    steps = [s.strip() for s in resp.content.strip().splitlines() if s.strip()][:3]
    print(f"[NODE plan] 产出计划：{steps}")
    return {"plan": steps, "results": []}


# ---- 节点 2：执行 —— 逐步完成计划，结果追加进 State ----
def act_node(state: PlanState):
    for i, step in enumerate(state["plan"], 1):
        print(f"\n[NODE act] 执行步骤 {i}/{len(state['plan'])}：{step}")
        resp = llm.invoke(f"执行任务中的一步，给出简洁结果。\n任务：{state['task']}\n步骤：{step}")
        print(f"[NODE act] 步骤 {i} 结果：{resp.content[:80]}...")
        state["results"].append(f"步骤{i}({step})：{resp.content}")
    return {"results": state["results"]}


# ---- 节点 3：汇总 —— 把各步结果合成最终答案 ----
def sum_node(state: PlanState):
    print("\n[NODE sum] 汇总各步结果")
    resp = llm.invoke(
        "把以下各步结果汇总成最终回答。\n" + "\n".join(state["results"])
    )
    return {"answer": resp.content}


def main():
    # ---- 画图：节点是函数，边是流转规则 ----
    g = StateGraph(PlanState)
    g.add_node("plan", plan_node)
    g.add_node("act", act_node)
    g.add_node("sum", sum_node)
    g.add_edge(START, "plan")
    g.add_edge("plan", "act")
    g.add_edge("act", "sum")
    g.add_edge("sum", END)
    app = g.compile()   # 传 checkpointer=... 即获得断点恢复/人审能力

    print("图的流转：START -> plan -> act -> sum -> END")
    final = app.invoke({"task": TASK, "plan": [], "results": [], "answer": ""})
    print("\n" + "=" * 60)
    print("最终答案：\n" + final["answer"])


if __name__ == "__main__":
    main()
