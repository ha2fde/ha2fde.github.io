Toolformer：让语言模型学会自己用工具

2026-07-27 · 约 15 分钟 · LLM 进化史 ⑧

2023 年 2 月，Meta AI 的 Schick 等人发表了 Toolformer——一篇简洁而优雅的论文：《Toolformer: Language Models Can Teach Themselves to Use Tools》。

核心思想：让语言模型自己学会在什么时候调用什么工具，而不是由开发者硬编码工具调用规则。

一句话定位：Toolformer 解决了 LLM 的「纯文本局限」——模型只能生成文本，无法查询外部信息、无法精确计算、无法更新知识。Toolformer 让模型自己决定何时调用外部工具来弥补这些局限。

一、为什么需要工具？

标准语言模型有三大固有缺陷：

缺陷示例工具解决方案
知识截止"2023 年世界杯冠军是谁？"调用搜索引擎
数学不好"234 × 567 = ?"调用计算器
事实幻觉编造不存在的信息调用知识库/维基百科

人工设计规则让模型调用工具的问题是：你无法预见到模型所有可能需要调用工具的场景。Toolformer 的想法是让模型自我学习。

二、核心方法：自学工具调用

图1：Toolformer 的三步自学流程。模型自己学会什么时候调用工具、调用什么工具。

具体来说，采样阶段模型在每个位置判断是否调用工具，生成类似这样的调用：

用户问：2020 年东京奥运会主办国是哪个国家？
模型生成：2020 年东京奥运会主办国是 [QA(东京奥运会主办国)] → 返回 [日本]

最终输出：2020 年东京奥运会主办国是日本。

三、支持的工具

Toolformer 支持 5 种工具，全部通过模型自学调用：

工具用途调用示例
问答模型回答事实性问题[QA(问题)]
维基百科搜索查找最新信息[WikiSearch(关键词)]
计算器精确数学计算[Calculator(表达式)]
日历查询日期信息[Calendar()]
机器翻译跨语言翻译[MT(文本, 目标语言)]

四、关键结果

Toolformer 的核心实验设计巧妙：对比使用工具前后的损失变化。如果调用工具后模型的预测损失显著降低，说明工具调用是有效的。

  • 工具调用使模型在需要外部知识的任务上表现显著提升
  • 模型学会了在适当场景自主决定调用工具——不是在所有位置都调用
  • 模型能够组合多个工具解决复杂问题
  • 不降低原始语言建模能力——工具调用是附加能力，不是替代

五、深远影响

Toolformer 的思想被后续几乎所有 Agent 框架继承：

  • Function Calling API：OpenAI 在 2023 年 6 月推出的函数调用功能，本质是 Toolformer 的工程化版本
  • MCP（Model Context Protocol）：Anthropic 的统一工具调用协议
  • Gorilla / APIBench：专门针对 API 调用的训练方法
  • 每个 Agent 框架：核心都是「模型自主决定调用什么工具」

一句话总结：Toolformer 教会了模型「什么时候该用工具」。它把 LLM 从一个只能生成文本的系统变成了可以操作外部世界的信息枢纽——这是通往 Agent 的关键一步。
