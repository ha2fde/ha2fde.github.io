第 1 章 · 文字数字化

机器真的"懂"文字吗？

① 你可能的疑惑"语音助手都能听懂我说话了，机器不是早就懂文字了吗？"
② 点破卡点机器里只有高低电平，它从没"见过"文字。文字、图片、声音进计算机的第一件事，都是变成数字——后面所有故事都建立在这之上。
     你看到的                机器看到的
 ┌────────────┐      ┌───────────────────────┐
 │ "猫"        │  →   │ 231, 140, 171  (字节)  │
 │ 一张猫的照片 │  →   │ 255, 200, 180, 45, …  │
 │ 一段猫叫声   │  →   │ 0.12, -0.87, 0.33, …  │
 └────────────┘      └───────────────────────┘
        机器世界里只有一种数据：数字
一句话说清数字化解决"机器无法表示文字"——一切先变数字，机器才能接手。
④ 数据流 · Python
text = "猫"
numbers = text.encode("utf-8")  # 文字 -> 字节
print(list(numbers))         # [231, 140, 171]
第 2 章 · 上

编号不是意思：one-hot 的死胡同

① 你可能的疑惑"词变数字还不简单？给每个词编个号不就行了。"
② 点破卡点编号里没有"意思"。"猫"是 3 号、"狗"是 4 号，3 和 4 挨得近，不代表猫和狗像。机器拿到的只有"一样 / 不一样"，永远算不出"有多像"。
 词表 = ["我", "爱", "猫", "狗", …]   共 50000 个词

 "猫" → [0, 0, 1, 0, 0, 0, …, 0]   ← 第 3 位是 1，其余全 0
 "狗" → [0, 0, 0, 1, 0, 0, …, 0]   ← 第 4 位是 1，其余全 0

 这只是一个"位置号码"：
   "猫"和"狗"的距离  ==  "猫"和"汽车"的距离
   → 语义信息：零
一句话说清one-hot 让每个词有了数字表示，但表示里不含语义——这正是下一个瓶颈的入口。
④ 数据流 · Python
vocab = ["我", "爱", "猫", "狗"]
onehot = {w: [int(i == j) for i in range(4)]
          for j, w in enumerate(vocab)}
print(onehot["猫"])  # [0, 0, 1, 0] 只是位置号
第 2 章 · 下

embedding：词义 = 向量

① 你可能的疑惑"那怎么让数字带上意思？"
② 点破卡点需要的不是"编号"，而是"坐标"：让意思相近的词，坐标也相近——"像不像"从此变成"距离近不近"，机器就能算了。
        语义空间（几百维，压成 2 维示意）
   高 │
 王   │     ●国王            ●女王
 室   │            ●男人   ●女人
      │
 水   │          ●苹果(水果)
 果   │    ●香蕉
      └──────────────────────────→

 关键性质：方向也带含义   国王 − 男人 + 女人 ≈ 女王
 坐标不用人设计：读够多文本，"上下文相似的词"会自动凑到一块儿
一句话说清embedding 解决"数字没有语义"——词义被编码成向量，语义相近则向量相近。（动手：附录脚本 1 embedding_demo.py）
④ 数据流 · Python
vec = embeddings["猫"]      # 几百维浮点数组
similarity(embeddings["猫"], embeddings["狗"])  # 0.78
similarity(embeddings["猫"], embeddings["车"])  # 0.12
第 3 章 · 语言模型任务

机器怎么学会"造句"？——从 n-gram 起步

① 你可能的疑惑"词能表示了，可'造句'对机器来说到底是个什么任务？"
② 点破卡点造句不是一口气生成，而是一连串"下一个词该接什么"的小决定。全篇主线任务：给定前文，预测下一个词。最早的解法朴素到可爱：数频次。
 主线任务：预测下一个词   "我 今天 想吃 ___" → 饭? 苹果? 火锅?

 n-gram 的做法：翻统计表（历史上"想吃"后面接过什么）
   "想吃" → 饭×80   苹果×45   火锅×30  …   谁次数多谁赢

 两个致命伤：
 ① 组合爆炸：前 3 个词的组合数 = 词表³，表根本装不下
 ② 没有泛化："他想吃 ___"表里没见过 → 直接抓瞎
   （明明和"我想吃"很像，但表格不懂"很像"）
一句话说清n-gram 用"统计前文后最常接什么"来预测，直观但只会死记硬背。（动手：附录脚本 2 ngram_demo.py）
④ 数据流 · Python
for a, b, c in sliding_windows(words, n=3):
    counts[(a, b)][c] += 1   # 前文 -> 下一个词
next_word = most_common(counts[("想", "吃")])
第 4 章 · 神经网络登场

神经网络来干什么？——不记死词，学规律

① 你可能的疑惑"统计表不够用了，加个'神经网络'到底多干了什么？"
② 点破卡点n-gram 是背答案：装不下所有组合，更不会举一反三。要换成"学规律"：相似的前文应该给出相似的预测——前文是向量，"像不像"终于能算了。
 前文词向量 → [加权变换] → [加权变换] → [加权变换] → 词表上每个词的概率
 "我 今天 想吃"                                   饭    0.41
                                                 苹果  0.27
                                                 火锅  0.18
                                                 …（其余 5 万个词）

 关键：输入是向量
 "他喜欢吃苹果" ≈ "我喜欢吃苹果"（向量相近）
 → 输出概率自动相近 = 举一反三，没见过也能猜
 权重怎么来？预测错了就微调，重复亿万次（细节本篇不展开）
一句话说清神经网络解决"背不下、不会类推"——把查表换成学规律，向量进、概率出。
④ 数据流 · Python
x = embed(context_words)      # 前文 -> 向量
h = layer3(layer2(layer1(x))) # 若干层加权变换
probs = to_vocab_probs(h)     # -> 每个候选词的概率
第 5 章 · 序列问题

读句子的方式为什么重要？——RNN 的顺序瓶颈

① 你可能的疑惑"句子有先有后，神经网络怎么'读'一串词？一个个读不就行了？"
② 点破卡点早期标准答案 RNN/LSTM 就是逐词顺序读、滚动更新"记忆"。两个治不好的病：慢——前一个不算完下一个不能开始，GPU 干瞪眼；健忘——读到句尾，句首已被冲刷干净。
 RNN 顺序读：
  我 → 今天 → 想 → 吃 → …
  ↓     ↓    ↓   ↓
 [记忆]→[记忆]→[记忆]→[记忆]→…   第 1000 个词要等前 999 个算完

 长句实测：
 "我出生在中国，……（隔了 50 个词）……所以我说一口流利的 ___"
 读到结尾时，"中国"的信息已磨损殆尽 → 填不出"中文"

 病根：信息只能从前往后、挤一条缝传过来
一句话说清RNN 用"顺序读 + 滚动记忆"处理序列，慢且记不住长的——瓶颈就在"顺序"本身。
④ 数据流 · Python
memory = init()
for word in sentence:            # 只能顺序循环
    memory = rnn_step(memory, embed(word))
probs = predict(memory)          # 用最后的记忆预测
第 6 章 · 上

注意力：让每个词"看全局"

① 你可能的疑惑"不顺序读，机器怎么知道每个词在句子里是什么意思？"
② 点破卡点RNN 的病根是"信息只能排队往前挤"。反过来：每个词确定自己含义时，直接同时看整句话所有词，重点看跟自己相关的。词义不再是死的——由上下文现场决定。
 句子："我 买了 一部 苹果 手机"

 确定"苹果"的含义时，它同时看所有词（线粗 = 关注多）：

           我  ············  弱
   苹果 →  买了 ───────────  中
           手机 ═══════════  强 ← 重点！
           一部 ············  弱

 "苹果"的新向量 = 全句按关注度加权汇总
 → 挨着"手机"它是公司，挨着"吃"它是水果
一句话说清注意力解决"看不见全局"——词义由上下文决定，任意两个词都能直接连线，不管隔多远。
④ 数据流 · Python
for word in sentence:                     # 每个词
    scores = relevance(word, sentence)    # 与全句算相关度
    meaning[word] = weighted_sum(sentence, scores)
第 6 章 · 下

注意力的副产品：顺手治好了"慢"

① 你可能的疑惑"看完上下文之后呢？这跟 RNN 比到底赢在哪？"
② 点破卡点每个词"看全句"这件事互相不用等——"苹果"看它的，"手机"看它的，所有词同时算。RNN 的"慢"被一起治了：GPU 终于火力全开。
   我     买了    一部    苹果    手机
   ↓      ↓      ↓      ↓      ↓
 ┌──────────────────────────────┐
 │  各自看全句，同时算，互不等待  │ ← 一次矩阵运算全部算完
 └──────────────────────────────┘
   ↓      ↓      ↓      ↓      ↓
  新向量  新向量  新向量  新向量  新向量
 （每个新向量都"泡过"整句上下文）

 对比 RNN：必须等"苹果"算完，才能开始算"手机"
 拿"泡过上下文"的向量去预测下一个词，质量远超那份"被冲刷的记忆"
一句话说清注意力天然并行——全局感知和速度，一次解决。
④ 数据流 · Python
# 所有词同时计算（矩阵运算，一次算完）
context_vecs = attention(embed(sentence))  # 并行
第 7 章 · 上

Transformer 到底是什么？——三件事

① 你可能的疑惑"Transformer 听起来很玄，是不是一个特别复杂的黑盒？"
② 点破卡点不玄，就是三块拼图各治一病——前两块你已经见过了。唯一的真问题：所有词同时看，不就不知道谁先谁后了吗？所以补一块"位置编码"。
 ① 注意力   → 全局感知（治"看不见全局"，第 6 章）
 ② 并行     → 治 RNN 的慢（第 5 章）
 ③ 位置编码 → 治"并行导致的乱序"：把"第几个词"直接加进向量

 输入: [词向量 + 位置戳]   ← 每个词自带"我排第几"
        ↓
 ┌────────────────────────┐
 │ 注意力：每个词看全句      │
 │ 变换层：加权变换提取规律  │
 └────────────────────────┘
        ↓  同样的块，堆几十层
 输出：每个位置的向量 → 预测下一个词的概率
一句话说清Transformer = 注意力（全局）+ 并行（快）+ 位置编码（不乱序）。三块各治一病，合起来就是全部。
④ 数据流 · Python
x = embed(tokens) + position_stamps  # 加位置戳
for block in blocks:
    x = block(attention(x))            # 同样的块堆叠
probs = vocab_head(x[-1])              # -> 下一个词概率
第 7 章 · 下

为什么赢的是它

① 你可能的疑惑"架构之争我看淡了——凭什么 Transformer 统一了江湖？"
② 点破卡点不是它更"聪明"，是它吃得下：并行让它能吃互联网级数据，注意力让它能学长距离规律。两者相加，才撑得起后面的"大力出奇迹"。
                RNN                     Transformer
 读法      逐词顺序，等前一个          所有词同时看
 速度      慢，GPU 大量闲置            并行，GPU 跑满
 长程信息  句首信息一路磨损            任意两词直接连线，距离无关
 能吃数据  小                         互联网级

 → 架构竞争的终点不是"谁巧妙"，是"谁能吃下更多数据"
一句话说清Transformer 赢在工程属性——并行吃数据、连线学长程，为规模化铺平了路。
④ 数据流 · Python
# 输入输出形式和从前一样：向量进，概率出
# 变的是中间：顺序挤记忆 → 并行看全局
probs = transformer(context_tokens)
第 8 章 · 上

预训练：在海量文本上练"续写"

① 你可能的疑惑"架构是骨架，可模型的'知识'到底从哪灌进去的？"
② 点破卡点答案简单得不像话：把互联网文本切成无数道"前文 → 下一个词"练习题，反复做、错了就调权重。不需要人工标注——原文的下一个词就是标准答案。
 互联网海量文本 → 自动切成练习题（免费，要多少有多少）
   "巴黎是法国的___"   答案："首都"（原文自带）
   "水在零度会___"     答案："结冰"
 亿万道题 × 反复练习 → 权重慢慢调好 = 基础模型

 练完它会的不只是接词：语法、常识、推理雏形都被压进权重

 两条路线：
   GPT：从左往右"续写" → 擅长生成（写、说、编）
   BERT：遮住中间"填空" → 擅长理解（分类、检索）
 生成式应用爆发，走的是 GPT 路线
一句话说清预训练解决"知识从哪来"——用文本自身当答案，在海量续写练习中学会语言。
④ 数据流 · Python
for text in internet_corpus:          # 海量文本
    context, answer = text[:-1], text[1:]
    err = model.error(context, answer)  # 错多少
    adjust_weights(err)                 # 错了就微调
第 8 章 · 下

微调：从"会背书"到"会干活"

① 你可能的疑惑"会续写 ≠ 会干活。我要它当客服、写代码，怎么办？"
② 点破卡点不用从头再练。预训练已把"语言本身"学完（贵，但只练一次）；之后用少量任务样本再练一小段——这叫微调。分工：预训练学语言，微调学干活。
 预训练（贵，一次）          微调（便宜，随便多少次）
 海量文本 → 基础模型 ──┬─ + 客服对话样本 → 客服机器人
 （续写练习）          ├─ + 代码样本     → 编程助手
                      └─ + 法律文书样本 → 法律助手

 类比：预训练 = 读完整个图书馆；微调 = 入职培训
一句话说清微调解决"通用不会干活"——在基础模型上用少量样本二次训练，便宜的定制化。
④ 数据流 · Python
base = load_pretrained()               # 预训练权重
for sample in task_samples:            # 少量任务样本
    adjust_weights(base.error(sample)) # 再练一小段
第 9 章 · 规模

为什么模型越大越强？——缩放定律与涌现

① 你可能的疑惑"为什么不'设计'一个更聪明的模型，而是一门心思越堆越大？"
② 点破卡点因为"变大"本身就是可靠的进步路线：参数量、数据量、算力同步放大时，错误率平滑持续下降（缩放定律）。更意外的是涌现——有些能力小模型几乎为零，过了某个规模突然就会了。
 预测错误率 │╲
           │ ╲___ 随规模平滑下降，还没看到头（缩放定律）
           │
 某项能力  │           ····· 大到一定程度：突然会了（涌现）
           │ ········· 小模型：几乎为零
           └──────────────────────→ 参数↑ 数据↑ 算力↑（同步放大）

 直觉：足够大的"预测下一个词"机器，
 为了把预测压得更准，被迫学会了语言背后的规律
一句话说清缩放定律解决"怎么稳定变强"——规模同步放大，能力非线性提升，这就是"大力出奇迹"的依据。
④ 数据流 · Python
# 训练流程和第 4 章的小模型一模一样
# 唯一变化：模型更大、数据更多、算力更足
train(big_model, big_data)
